AI 消费级产品

ChatGPT · Claude · Gemini · Kimi · DeepSeek · MiniMax — UX 变化与功能发布

ChatGPT OpenAI 2026.07.16 ~ 07.17
  • 桌面 App 恢复 sidebar 历史与 Projects（07.16）—— 上期「超级 App」改版把对话历史移出侧栏、Projects 入口下沉，引发社区强烈反弹；本周官方 release notes 把历史记录与 Projects 恢复到 sidebar，回到用户熟悉的导航结构。
  • 重建 ChatGPT / Codex 全局切换器（07.16）—— 顶部新增 ChatGPT / Codex 全局切换，ChatGPT 内再分 Chat / Work 两栏；Unified Recents 统一近期列表，跨设备的 Cloud Work 同步、Local 任务留在本机。
  • 官方公开承认改版「没完全做对」（07.17）—— Tibo Sottiaux 在 X 发文回应，坦言新版「didn't get totally quite right」；从改版到回滚仅 8 天，被外媒类比为软件版「New Coke」。
ChatGPT 桌面这 8 天的「改版—反弹—回滚」是本周最值得抄进设计复盘的案例:① 高频入口的位置是"肌肉记忆资产",不能一次性挪走——把对话历史移出 sidebar 看似是"信息架构升级",但用户每天点它几十次,位置本身就是资产;要迁移必须留旧位置的"过渡指引"或允许一键切回,而不是直接消失。② 产品线切换器要"全局常驻 + 层级清晰"——ChatGPT / Codex 全局切换 + Chat / Work 二级分栏,是"多产品线合并"的正解:顶层切大类、次层切模式,而不是把所有东西塞进一个扁平列表。③ 回滚要配一句"人话道歉"——Sottiaux 那句"没完全做对"比任何 release note 都管用;承认错误 + 快速修正,是把"改版翻车"转化为"信任加分"的唯一路径。高频入口迁移三件套:旧位置留跳转指引 + 新位置高亮引导 + 设置里可切回;产品线切换 = 顶层全局切换器(ChatGPT / Codex)+ 二级模式栏(Chat / Work),常驻不折叠;Unified Recents 跨设备合并 · Cloud / Local 用图标区分同步范围;回滚公告 = 首屏 banner + 具名负责人"人话"说明(不用模板腔);改版灰度必须留"一键回到旧版"开关至少 30 天。

Claude Anthropic 2026.07.20
  • Fable 5 逆转「限额」成 Max / Team Premium 标配（07.20 生效）—— 此前计划把 Fable 5 限入付费加购，六周内三度延期（07.08 → 07.13 → 07.19）；本周官方逆转，Max（5x $110 / 20x $220）与 Team Premium（$100）直接包含 Fable 5，含 50% 周限额。
  • Pro / Team Standard 一次性 $100 额度过渡（07.20）—— 未含标配的档位先发一次性 $100 使用额度作缓冲，用完后转 $10 / $50 计量计费；用"先送额度再计费"平滑掉定价切换的抵触感。
  • Claude Code 速率提升延至 8 月（07.20）—— 原定本周到期的 Claude Code 速率提升延期至 8 月 19 日；官方把逆转归因于 GPT-5.6 Sol（07.09）与 Kimi K3（07.16）接连施压的竞争环境。
Claude 这次"额度政策逆转"给订阅制 AI 上了一堂定价 UX 课:① 付费档的"包含什么"要一眼可读,不能藏在计量细则里——Max / Team Premium 直接"包含 Fable 5"这句话本身就是转化钩子;用户买的是确定性,"标配"比"加购"更能降低决策成本。② 定价切换必须留"缓冲额度"而非硬断——给 Pro / Team Standard 先发一次性 $100 额度再转计量,是把"涨价 / 收紧"从"突然断供"变成"平滑过渡"的经典手法;用户对"先体验后计费"的接受度远高于"直接掏钱"。③ 竞品节奏会倒逼你的额度策略——官方直言逆转受 GPT-5.6 与 Kimi K3 施压;定价页设计要预留"快速调整"能力(标配项、限额比例、过渡额度都应是可配置参数,而非写死的文案)。付费档卡片首行 = "包含 [旗舰模型]"加粗(标配 vs 加购一眼分);周限额可视化 = 环形进度 + "已用 / 上限"数字(50% 限额别只写百分比);定价切换缓冲 = 一次性额度 + 倒计时 + 到期前 3 次提醒;计量计费单价($10/$50)与标配档并列展示(让用户自己算账);"速率提升延期"用 banner 明确新日期(不含糊说"稍后");额度政策参数化(标配 / 限额 / 过渡额度可后台热调)。
来源：ai-news.ge · Anthropic reverses Fable 5 cutoff (07.20) · x.com · @claudeai (07.18 宣布) · aitoolsrecap · Fable 5 returns to Max / Team Premium
Gemini Google 2026.07.16 ~ 07.21
  • Gemini 3.5 Pro 旗舰发布再延数月（07.16 彭博）—— 代号 Cappuccino（原计划 2M 上下文 + Deep Think）连错三个发布截止日，团队放弃原底座重新预训练；消息当日 Alphabet 股价一度跌约 4.4%，旗舰节奏首次被资本市场公开质疑。
  • 三款效率模型补位发布（07.21）—— Gemini 3.6 Flash（$1.5/$7.5、token 用量 -17%、DeepSWE 49% vs 前代 37%、知识 cutoff 推进到 2026-03）；3.5 Flash-Lite（$0.3/$2.5、350 tok/s）；Flash Cyber 安全专用，仅政府 / 可信伙伴限量试点。
  • "旗舰跳票 + 效率补位"叙事成型（07.16~21）—— 一边是旗舰延期，一边把效率档打到极致性价比;Google 用"能马上交付的效率模型"稳住开发者预期,同时给旗舰争取重训时间。
Gemini 这一周的"旗舰跳票 + 效率补位"是产品沟通的教科书正反面:① 旗舰跳票的最大伤害不是延期,而是"沉默"——连错三个截止日、放弃底座重训,如果不主动沟通,市场会用最坏的方式脑补(股价 -4.4% 就是代价);发布 roadmap 的 UX 原则是"宁可给区间不给死线,一旦定了就要兑现或提前说明"。② 用"效率档"承接旗舰跳票的注意力是聪明的产品节奏——3.6 Flash 把 token 用量降 17%、Flash-Lite 打到 $0.3/$2.5,是"我们没交旗舰,但给了你今天就能用的省钱货";这条对做模型 / API 产品的团队直接:发布节奏要有"稳定档"托底,不能把所有筹码押在一次旗舰上。③ 定价与能力要在同一张对比表里说清——三款模型三种价位三种场景,用户最需要的是"我该选哪个"的决策表,而不是三篇独立公告。Roadmap 展示 = 时间区间(Q3)而非死线(某月某日);延期要主动发"进度说明"(不沉默 = 不被脑补);效率档对比表三列:3.6 Flash / 3.5 Flash-Lite / Flash Cyber × 价格 · 速度 · 适用场景;token 用量 -17% 用"同任务对比图"而非纯数字;Flash Cyber"限量试点"标清准入门槛(政府 / 可信伙伴)避免用户空等;知识 cutoff 日期(2026-03)显式标注在模型选择器。
来源：新浪财经 · 引彭博 Gemini 3.5 Pro 延期 (07.17) · 9to5google · Gemini 3.6 Flash launch (07.21) · blog.google · Gemini 效率三模型
Kimi K3 Moonshot AI 2026.07.16
  • 开源 frontier 模型发布（07.16）—— 2.8T 参数、1M 上下文、$3/$15 定价；Arena Frontend Code 榜首超越 Claude Fable 5，Artificial Analysis Index 位列第 4；模型权重定于 07.27 开放，可自部署。
  • "顶级代码能力 + 开放权重"组合（07.16）—— 首次把前端代码生成的第一梯队能力放到"可下载自部署"的形态；对依赖闭源 API 的团队构成"用同等能力换掉计量账单"的现实选项。
  • 发布即施压竞品定价（07.16）—— Simon Willison 等评测者当日给出对比;Kimi K3 的定价与开放策略,被视为本周 Claude Fable 5 额度政策逆转的外部压力之一。
Kimi K3 用"开源 frontier"这一手,把行业的 UX 讨论从"界面"拉回到"分发形态":① 开放权重本身就是一种产品体验承诺——"可自部署"意味着用户不再被单一厂商的额度 / 限流 / 涨价绑架;做闭源 API 产品的团队要意识到,当同等能力可以"下载带走"时,你的护城河只剩"托管体验 + 生态 + 稳定性",定价必须更透明。② 榜单成绩要落到"可复现的对比场景"——Arena Frontend Code 榜首这类成绩,用户真正关心的是"在我的前端任务上到底强多少";发布页应配"同一 prompt 三模型并排结果",而不是只甩一个榜单名次。③ "权重开放日"要当成一次产品节点来运营——07.27 开放权重是继发布之后的第二次高峰;产品应把"发布 → 权重开放 → 生态接入"设计成有节奏的多幕,而非一次性抛出。开放权重 = 分发形态卖点,发布页显式标"可自部署 / 可商用"边界;榜单成绩配"同 prompt 并排结果"可复现对比(而非纯名次);定价 $3/$15 与"自部署零 API 费"两条路径并列(让用户按规模选);1M 上下文用"能装下多少代码 / 文档"的具象化说明;"权重开放日"(07.27)做成倒计时节点 + 接入指引;开源模型的信任锚 = 许可协议 + 复现脚本 + 评测集公开。

企业级 AI 平台
ChatGPT Enterprise / Edu / Business OpenAI 2026.07.16 ~ 07.17
  • 桌面回滚同步覆盖企业席位（07.16）—— sidebar 历史与 Projects 恢复、ChatGPT / Codex 全局切换器重建等改动，对 Enterprise / Edu / Business 席位同步生效；企业侧免去了大规模内部培训的返工。
  • Cloud Work / Local 任务范围区分（07.16）—— Unified Recents 之外，跨设备同步的 Cloud Work 与仅留本机的 Local 任务被显式区分，便于企业按数据驻留要求管控哪些任务可上云。
  • 改版回滚的合规意义（07.17）—— 官方承认改版「没完全做对」并快速回滚，对受监管行业客户是正向信号：核心导航不会在没有过渡期的情况下被单方面重构。
企业视角看这次桌面回滚,有两条比消费端更硬的原则:① 企业席位的 UI 变更必须有"变更公告 + 过渡期"契约——消费用户改版顶多抱怨,企业客户则要重排培训、更新内部文档、通知合规;核心导航"说改就改"会直接冲击续约信任,产品应给企业管理员一个"变更预告 + 灰度开关 + 回退窗口"的三段式契约。② Cloud / Local 任务范围要成为可管控的一等属性——把 Cloud Work 与 Local 任务显式区分,不只是同步体验,更是数据驻留合规的抓手;企业管理员需要能按"任务是否上云"来配策略,这一属性应进入 Admin 面板而非埋在用户端。企业 UI 变更契约三段:预告(≥2 周)+ 灰度开关(管理员可控)+ 回退窗口(≥30 天);Cloud / Local 任务 = 可管控属性,进 Admin 策略面(按数据驻留分域);Unified Recents 企业版需支持"按团队 / 项目过滤";改版回滚公告同步推送企业管理台(不止消费端 banner);核心导航变更走"重大变更"评审(与定价变更同级)。

Claude Team / Enterprise Anthropic 2026.07.20
  • Team Premium 标配 Fable 5（07.20）—— Team Premium（$100 席位）直接包含 Fable 5 与 50% 周限额；Team Standard 走一次性 $100 额度 → $10/$50 计量的过渡路径，团队管理员可按席位分配不同档位。
  • 过渡额度的团队分发（07.20）—— 一次性 $100 额度以团队为单位发放，管理员可在成员间再分配，避免"人均一份用不完 / 重度用户不够用"的额度错配。
  • Claude Code 企业速率提升延至 8 月（07.20）—— 面向团队的 Claude Code 速率提升延期至 8 月 19 日；对依赖 Claude Code 做工程协作的团队，官方给出了明确的新时间点而非模糊承诺。
Claude 把额度政策落到团队场景,暴露出企业订阅最容易翻车的两个点:① 团队额度不能"人均切一份",要支持"池化 + 再分配"——重度用户和轻度用户的用量差几十倍,平均分配等于同时得罪两头;过渡额度以团队为池、管理员可再分配,才是符合真实协作的模型。② 席位档位与"包含的模型 / 限额"要在管理台一屏可视——管理员最怕"不知道每个席位到底能用什么";Team Premium 含 Fable 5、Standard 走计量,这类差异应在席位管理页用矩阵一眼呈现,而不是让管理员去翻计费文档。③ 速率 / 额度变更要给团队"明确新日期"——延期到 8 月 19 日这种确定信息,比"稍后恢复"对企业规划友好得多。团队额度 = 池化模型 + 管理员再分配(不强制人均);席位管理页 = 席位 × 档位 × 含模型 × 限额 四列矩阵;过渡额度用量可视 = 团队总额度环形 + 成员用量条形;计费切换前置提醒(团队管理员 + 财务角色双通知);速率延期给"明确日期"(8/19)不用模糊词;档位差异做成"对比表"入口挂在升级按钮旁。

Gemini for Workspace / Enterprise Google 2026.07.21
  • 3.6 Flash 面向企业 API 放量（07.21）—— 效率旗舰 3.6 Flash（$1.5/$7.5、token 用量 -17%）面向 API 与 Enterprise 推开；对成本敏感的企业批处理场景，"同任务更省 token"直接转化为账单下降。
  • Computer Use 内置 API / Enterprise（07.21）—— Gemini 的 Computer Use 能力进入 API 与 Enterprise，Agent 可在受控环境操作界面完成跨应用任务；企业侧可按权限限定可操作的应用范围。
  • CodeMender 安全能力"上链但拴绳"（07.21）—— 配合 Flash Cyber，CodeMender 走 scan → verify → remediate 的自动修复闭环，但保留人工复核关卡；SiliconAngle 形容为"给 bug hunter 上了 API 却仍拴着绳"。
Gemini 把效率与安全能力同步推进企业侧,给出两条 B 端 AI 的产品原则:① 降本要能"被算清":省 token = 省钱要在控制台可见——3.6 Flash 的"token 用量 -17%"对企业最有说服力的呈现,不是发布会 PPT,而是账单页里"同任务同比节省"的对比曲线;企业采购决策靠数据,不靠形容词。② Agent 操作界面能力必须"内建人工关卡"——Computer Use 让 Agent 能点按真实界面,风险陡增;CodeMender 的 scan / verify / remediate 保留人工复核,正是"自动化但不失控"的范式;做 Agent 产品要把"人工审批节点"设计成不可跳过的一等公民,而不是可选项。③ 安全 / 敏感能力用"限量试点 + 可信伙伴"分级放量——Flash Cyber 只给政府 / 可信伙伴,是对高风险能力的克制;能力越强,准入门槛越要显式、分级、可审计。降本可视 = 控制台"同任务同比节省 token / 成本"曲线(不止发布会数字);Computer Use 企业版 = 可操作应用白名单 + 每步操作日志;Agent 人工关卡 = scan → verify →(人工复核)→ remediate,复核不可跳过;高风险能力分级放量:公开 / 可信伙伴 / 政府三档,准入门槛显式;CodeMender 修复建议留"接受 / 拒绝 / 改写"三选项(不自动 merge);敏感能力操作全程 audit trail。

对我们的启示

从 07.16 ~ 07.22 这一周产品动态中提炼的 6 条具体、可执行的设计建议

Insight · 01
↗ ChatGPT 桌面回滚 · 超级 App 反弹
高频入口是"肌肉记忆资产",迁移必须留退路
ChatGPT 桌面从改版到回滚只用 8 天，核心教训极其具体:用户每天点几十次的入口（对话历史、Projects），其位置本身就是资产——移走它引发的负面情绪，远大于任何新功能带来的正面价值。改版自检的第一问永远是"现有用户会不会找不到东西"，而不是"这样像不像那个更火的产品"。第二条:高频入口若必须迁移，"旧位置留指引 + 新位置高亮引导 + 设置里可切回"三者缺一不可；直接让入口消失，等于单方面撕毁与用户的隐性契约。改版第一问:现有用户会不会找不到高频入口;导航变更走契约级评审(与定价 / 隐私同级);高频入口迁移三件套:旧位指引 + 新位高亮 + 可切回;反弹信号监测:历史 / 项目 / 搜索的负反馈单列告警;改版灰度保留"一键回旧版"≥30 天;竞品对标做能力对齐,不做界面照搬。
Insight · 02
↗ ChatGPT 官方承认"没完全做对" · 快速回滚
回滚是信任建立而非耻辱,但只有一次机会
Tibo Sottiaux 一句"didn't get totally quite right"，比任何 release note 都更能挽回信任:承认错误 + 快速修正，能把"改版翻车"转化为"我们听得进反馈"的口碑。做产品要有"回滚不是失败"的心态，快速纠偏比死撑更值得用户尊敬。但第二条同样重要:"敢回滚"只能是止损手段，不能成为迭代常态——若同类失误反复出现，"快速回滚"就会被解读为"不靠谱"；纠偏是稀缺资源，不能反复消费。回滚公告要用"人话"具名说明，而不是模板腔的更新日志。回滚公告 = 首屏 banner + 具名负责人"人话"说明(非模板腔);承认错误要早、要具体(说清哪里做错了);回滚是止损不是常态(同类失误反复=信任崩塌);把"感谢反馈"写进公告(明确回应社区);建立"重大变更后 72 小时反馈窗口"机制;纠偏后做公开复盘(把教训变团队资产)。
Insight · 03
↗ Claude Fable 5 标配化 · $100 过渡额度
定价切换要留"缓冲额度",标配比加购更能降低决策成本
Claude 把 Fable 5 从"限额加购"逆转为 Max / Team Premium"标配"，并给 Pro / Team Standard 发一次性 $100 额度过渡，是订阅制 AI 的定价 UX 范本:① 付费档"包含什么"要一眼可读——"标配旗舰模型"这句话本身就是转化钩子，用户买的是确定性，标配比加购的决策成本低得多。② 定价切换必须留"缓冲额度"而非硬断——"先送额度再计费"的接受度远高于"直接掏钱"，把涨价 / 收紧从"突然断供"变成"平滑过渡"。第三条:团队额度要"池化 + 再分配"，绝不能人均切一份，否则同时得罪重度和轻度用户。付费档首行"包含 [旗舰模型]"加粗(标配 vs 加购一眼分);定价切换缓冲 = 一次性额度 + 倒计时 + 到期前 3 次提醒;周限额可视化 = 环形进度 +"已用/上限"(50% 别只写百分比);团队额度池化 + 管理员再分配(不人均);计量单价与标配档并列(让用户自己算账);额度策略参数化(标配/限额/过渡额度后台热调)。
Insight · 04
↗ Gemini 3.5 Pro 跳票 · 三款效率模型补位
发布 roadmap 宁给区间不给死线,用"稳定档"托底旗舰风险
Gemini 3.5 Pro 连错三个截止日、股价一度跌 4.4%，而同周三款效率模型高调补位——这组对照给出发布节奏的硬原则:① 旗舰跳票最大的伤害不是延期，而是"沉默"；roadmap 要"宁可给区间不给死线，一旦定了就兑现或提前说明"，延期必须主动发进度说明，否则市场会用最坏方式脑补。② 用"效率档"承接旗舰跳票的注意力，是聪明的产品节奏——发布节奏要有"稳定档"托底，不能把所有筹码押在一次旗舰上。第三条:多档模型要在同一张对比表里说清"我该选哪个"，而不是三篇独立公告；降本要能被算清，"省 token = 省钱"要在控制台可见。Roadmap 用时间区间(Q3)不用死线;延期主动发进度说明(沉默=被脑补);多档模型对比表:价格 · 速度 · 场景三维;发布节奏留"稳定档"托底(不押注单次旗舰);token 用量优化用"同任务对比图"呈现;知识 cutoff 日期显式标在模型选择器。
Insight · 05
↗ Kimi K3 开源 frontier · $3/$15 定价
开源 frontier 冲击定价:护城河只剩托管体验与透明度
Kimi K3 用 2.8T 参数、1M 上下文、$3/$15、Arena Frontend Code 榜首，把"顶级代码能力"放到"可下载自部署"的形态，对整个行业的定价逻辑构成冲击:① 当同等能力可以"下载带走"，闭源 API 的护城河只剩托管体验 + 生态 + 稳定性，定价必须更透明，不能再靠信息不对称收费。② 榜单成绩要落到"可复现的对比场景"——发布页应配"同一 prompt 三模型并排结果"，而不是只甩榜单名次；用户信任来自能自己验证。第三条:"权重开放日"要当成一次独立产品节点来运营，把发布 → 权重开放 → 生态接入设计成有节奏的多幕。开放权重作为分发形态卖点(显式标可自部署/可商用边界);榜单配"同 prompt 并排结果"可复现对比;定价与"自部署零 API 费"两条路径并列(按规模选);闭源产品护城河重估:托管 + 生态 + 稳定性 + 透明定价;1M 上下文用"能装多少代码/文档"具象化;开源信任锚 = 许可协议 + 复现脚本 + 评测集公开。
Insight · 06
↗ Figma Workflow lab · 设计→代码→PR
设计交付从单程变双向,设计系统要为"可回流"重构
Figma Workflow lab 演示"用 Figma Make 直接部署设计"、改动作为 PR 回流工程仓库，把设计交付从单程推向双向:① 当设计改动能直接生成 PR，组件命名、token 结构、状态定义就不再只是"给人看"，而是"给代码生成器读 + 给 diff 引擎比对"——命名和结构的严谨度直接决定 PR 质量，设计系统要按"机器可读契约"重构。② 双向 handoff 需要"谁是 source of truth"的显式约定——设计改一版、工程改一版，最大的坑是互相覆盖；必须设计"变更来源标记 + 冲突可视 + 合并策略"三件套。第三条:AI 额度可见性是生产级信任的前提，设计师不会把黑盒计费的工具放进关键工作流。组件命名/token 作为机器可读契约纳入 lint;双向 handoff 三件套:变更来源标记 + 冲突高亮 + 合并策略;source of truth 显式切换(某组件以设计/以代码为准);PR 由设计生成时附"设计意图摘要"帮工程 review;handoff 历史 = 设计版本↔代码提交双向 timeline;AI credit 用量常驻可见(不藏计费页)。
