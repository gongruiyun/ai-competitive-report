AI 消费级产品

Claude · ChatGPT · Gemini · Kimi · DeepSeek · MiniMax — UX 变化与功能发布

ChatGPT OpenAI 2026.07.09 ~ 07.15
  • GPT-5.6 三档 GA（07.09）—— Sol（$5/$30）/ Terra（$2.5/$15）/ Luna（$1/$6）在 ChatGPT / Codex / API 全面推开；新增 max / ultra 能力等级；6 档模型选择器同步收敛为「档位 × 能力等级」二维矩阵。
  • ChatGPT Work 上线（07.09）—— 长任务 Agent，可跨应用与文件工作数小时；关键步骤 Pause / Approve，操作历史可回溯；Enterprise / Edu 席位 2 周 early access，之后分批向 Plus / Pro 开放。
  • ChatGPT Sites 公测（07.09）—— 自然语言描述 → 可交互网站 / 仪表盘 / 报告；生成物直接托管在 chatgpt.com/sites/<slug>；AI 生成物首次进入「有稳定 URL 的分享资产」形态。
  • 新桌面 App 合并三线（07.09）—— Chat / Work / Codex 从三个独立 App 收敛到单一入口，左栏 tabs 三选一切换；旧版保留为 ChatGPT Classic 供不适应的用户回退。
  • Search across chats / projects / files 增强（07.14）—— 顶栏搜索框首次覆盖历史对话、项目文件、上传附件、Memory 条目四类内容；跨类结果合并到同一 result list。
  • ChatGPT returns to WhatsApp in EEA（07.13）—— 欧洲经济区用户可在 WhatsApp 内直接对话 ChatGPT；离线消息通过 push 通知补齐，「AI 触点」再一次隐入日常消息 App。
这一周 ChatGPT 一次性发出「模型 + 产品线 + 分发面」三个大动作,可以浓缩成三条产品设计原则:① AI 产品线合并要留一条"回退旧版"的显式路径——把 Chat / Work / Codex 三个 App 收敛到一个入口是对的,但旧用户的心智不可能一夜切换,顶部或设置里保留一个 muted 的「回到 ChatGPT Classic」链接,是"我随时能走"的信任基础;强推单一入口=退订率飙升。② 长任务 Agent 的核心不是"能跑多久",而是"能被中断吗"——Work 的 Pause / Approve 双按钮把 Agent 从"黑盒"变成"半自动流水线",用户可以在开会时按 Pause,回来再按 Approve;界面得先设计好"打断态",再设计"执行态"。③ AI 生成物开始要 URL——Sites 让生成物挂上 chatgpt.com/sites/<slug>,意味着 AI 产物从"聊天记录里的一段文字"升级到"可被 Google 索引的资产";我们下一代设计要给"AI 生成产物"预留 URL slot、meta 面板、分享 sheet 三件套。「回到 Classic」muted 链接放设置抽屉底部(不当默认按钮);Work 三态:Running / Pause / Waiting for approval → Approve / Reject 双主 CTA + 无限撤销时间轴;Sites 生成物 = URL + og:image + 分享 sheet 三件套;搜索结果 4 类图标 12px + 类别 chip 色分组;WhatsApp 触点 = 联系人图标(不新增 tab);模型选择器 6 档 × 3 能力等级 = 二维矩阵而非纯列表。
来源：openai.com · GPT-5.6 is here · openai.com · ChatGPT for your most ambitious work · help.openai.com · Release Notes (Sites / Desktop / Search / WhatsApp)
Claude Anthropic 2026.07.14
  • Claude for Teachers 免费开放（07.14）—— 美国 K-12 认证教师可免费获得高级 Claude 席位；预装 教学 Skill 库（备课、评分、家长沟通模板、差异化学习）；对齐 50 州学术标准与 FERPA 学生隐私要求。
  • 教师身份认证机制（07.14）—— 使用学区邮箱 + SHEEO 数据库交叉核验；认证不通过留下"预备教师"过渡席位（限次数），避免"审核失败=直接封杀"的挫败体验。
  • Learning Commons 共享库（07.14）—— 教师之间可分享 prompt 模板、评分 rubric、differentiated learning 模板；首次让"教学 Skill"进入协作 / 共享层，而不只是个人预装。
Claude 这一周把"免费"这件事做出了新姿势:① AI 免费额度按"职业身份"发放比按"用户量"发放更精准——teachers 免费不是普世优惠,而是"这是你的职业工具";在 Skill 库、模板、术语上做垂直适配,才让教师觉得"这不是被施舍,是被理解"。② 身份核验的失败态要留"过渡席位"——SHEEO 数据库不可能百分百完备,认证不通过就"直接封杀"会伤害真实教师;留一个次数受限的预备席位,是产品礼貌与安全防滥用之间的合理妥协。③ 垂直 Skill 库应该内建"共享层"——Learning Commons 让教师之间可以互传 prompt / rubric / 教学模板,把 Skill 从"个人预装"进化到"社群共享",这条同样适用于其它垂直行业(金融、医药、法务)。身份核验三态:通过(全席位) / 预审(预备席位 + 倒计时) / 失败(申诉链接不是死胡同);Skill 库首页按"备课 / 评分 / 沟通"三分类 chip 而非无序列表;FERPA 合规提示写进 onboarding 首屏而非埋在设置;Learning Commons 共享按钮直接挂 Skill 卡右上;点赞 / 收藏 / fork 三种社群动作分开(不合并成一颗心)。

Gemini Google 2026.07.10 ~ 07.12
  • Workspace Gemini 管控 · admin / user 双层开关（07.10~12）—— 管理员可对 Docs / Drive / Gmail 分域禁用 Gemini；用户在个人设置里也能独立关闭；同一功能出现"组织层 + 个人层"的可组合开关。
  • Fill with Gemini 面向 Business Standard 起步 rollout（07.10）—— Docs 表格「Fill with Gemini」列填充自本周起面向 Business Standard 席位分批放量；给出示例，Gemini 按模式扩展到剩余行；企业管理员可对敏感字段强制关闭该功能。
  • Gemini 3.5 Pro 启动预告（07.11）—— 7 月 17 日进入 Workspace 全量灰度；Gemini 3.5 Pro 的核心卖点是"分文档 / 分表格 / 分对话"的分域上下文管理。
Gemini 这一周的动作说明企业 AI 的"关掉"能力和"打开"能力一样重要:admin / user 双层开关是"AI 治理"的标配——组织层负责合规、个人层负责心理安全,两层同权且可读,单独一层都不够。第二条:「Fill with Gemini」把 AI 从对话式换成了表单式——用户不再"问 AI",而是"给示例让 AI 归纳";这条对 B 端数据处理产品是启发:凡是能用"给例子 + 扩展模式"完成的任务,不要再套一个 chat 对话框,直接把入口挂到列头。admin / user 双层开关矩阵:「关」/「允许开」/「强制开」三态;Fill with Gemini 入口挂列头(不套 chat);示例 → 模式 → 预览 → 应用 四步进度条(每步可编辑);分域上下文 chip:文档 / 表格 / 对话 三色不同(不用色块用形态);Workspace Gemini 关闭按钮不藏,放设置一级页面。

企业级 AI 平台
ChatGPT Enterprise / Edu / Business OpenAI 2026.07.09 ~ 07.14
  • ChatGPT Work 企业首批预览（07.09）—— Enterprise / Edu 席位获得 2 周 early access；管理员可控制哪些角色可发起长任务、哪些工具可被 Agent 调用；Pause 状态支持"跨席位交接"（甲发起 → 乙审批 → 丙继续）。
  • ChatGPT Sites 组织级开关（07.09）—— 管理员可"允许 / 禁用 / 仅内部可见"三态控制 Sites 发布路径；企业侧的 Sites 可自动挂公司 slug 前缀，避免品牌混淆。
  • GPT-5.6 成为 Microsoft 365 Copilot 首选模型（07.09）—— Copilot Chat / Word / Excel / Outlook 里默认调用 Sol；企业管理员在 Microsoft 365 Admin Center 中控制模型接入策略，「AI 采购」进一步向企业既有工具链靠拢。
  • Plugin Directory 取代 App Directory（07.09）—— 企业 IT 用统一命名（Plugin）代替新旧混杂的 App / Extension 术语；Workspace 设置里按"角色 / 状态 / 类别"三维筛选，管理员一站式治理。
  • Enterprise 增强搜索（07.14）—— 顶栏搜索首次覆盖历史对话、项目文件、上传附件、Memory 条目；企业管理员可控制哪些数据类型进入搜索索引，Sources 审计视图同步展开。
这一周企业级 ChatGPT 一次性推出了 Work / Sites / Search 三大能力,可以浓缩成三条:① 长任务 Agent 必须支持"跨席位交接"——不是所有决策都由发起人做完;甲发起、乙审批、丙继续是企业协作真实形态,状态机得设计好"授权流转"节点,而不是"一个人一路点到底"。② 组织级功能开关默认要"最保守"——Sites 默认应为"仅内部可见"而非"允许公开"(GDPR / SOC 2 合规默认原则);企业 IT 会先把默认值设成"关"才开始考虑打开,产品应该迎合而非对抗这个逻辑。③ AI 术语要向企业既有工具链靠拢——「App / Extension / Plugin」这类术语混用是企业采购最大摩擦点;OpenAI 这一步把它统一成 Plugin,是"减轻企业 IT 词汇负担"的正确方向;我们做 B 端产品也要审视自家术语列表,是否有旧新术语并存的"多语言"问题。Work 跨席位交接三阶段:发起 · 审批 · 继续,每阶段留操作抽屉(who/when/what);Sites 组织级开关默认为"仅内部可见"(禁用状态用灰锁 icon,允许状态用绿钩);Plugin Directory 三维筛选:角色 · 状态 · 类别;Sources 审计三列:timestamp / 编辑者 / 权限来源;Copilot 默认模型标注在设置一级页面 chip(而非二级抽屉);Enterprise 搜索索引类型开关 = 5 个 List Row + toggle 复选(chat / files / memory / sources / plugins)。

  • Claude for Teachers 教育版路径（07.14）—— 认证教师所属学区可批量升级到 Claude Enterprise Edu 席位；席位复用现有 Anthropic Console 治理面（IAM / 审计 / token 配额），教师从"个人 free tier"到"学区 Enterprise"零迁移成本。

Anthropic 这一周把"教师免费"演进为"学区批量升级"的路径,展示了一条B2C 到 B2B 的产品桥:① 个人免费席位与企业席位共享治理面——Free tier 用户切换到 Enterprise 时,不应该重建组织树、不应该丢失 Skill 库、不应该重新学习界面;这条对做 SaaS 的团队最直接:"个人 → 团队 → 企业"的升级路径必须无缝,任何数据丢失都会让企业 IT 打退堂鼓。② 审批记录要能"写出"到既有 SIEM——企业不会为了新工具改造整个安全事件流;做企业级 AI 就要提供 SIEM webhook / 事件订阅 / SCIM 用户同步这三样,把治理面与企业既有工具链拼接。③ Skill 库是企业级 AI 的护城河——垂直行业 Skill 库比通用 chat 更有粘性,teachers 的产品化路径可以直接被复用到金融合规、法务尽调、医药研发等场景。升级路径三步:个人 free → 团队 pro → 企业 Enterprise(数据 / Skill / 界面全保留);SIEM webhook 开关 + 事件类型多选(工具调用 / 越权 / 敏感数据);Skill 库分类树 = 行业 → 场景 → 具体 skill 三层;审批记录写入 SIEM 选项默认关(合规默认原则);「学区批量升级」独立入口(不藏在通用 pricing 页)。

Gemini for Workspace Google 2026.07.10 ~ 07.12
  • admin / user 双层 Gemini 开关（07.10~12）—— 管理员可对 Docs / Drive / Gmail 分域禁用 Gemini；用户在个人设置里也能独立关闭；两层开关矩阵形成「关 / 允许开 / 强制开」三态。
  • Fill with Gemini 面向 Business Standard 起步（07.10）—— 表格列填充：给出示例，Gemini 归纳规则并按模式扩展；企业管理员可对特定文档强制关闭该功能，避免敏感字段被 AI 自动补齐。
  • Gemini 3.5 Pro 全量灰度预告（07.17 启动）—— 分域上下文管理是核心卖点，企业可按文档 / 表格 / 对话粒度隔离敏感上下文；预告页面展示了「上下文域」这一新的信息架构概念。
Gemini for Workspace 这一周把「AI 管控」推到新高度:① 双层开关是企业 AI 治理的最低标准——组织层管合规、个人层管心理安全,任何一层缺失都会引起客户投诉;做企业 AI 产品必须原生支持这套矩阵,而不是"事后加一个开关"。② 表单式 AI 比 chat 式 AI 更适合数据密集场景——Fill with Gemini 把"提示 + 补全"两步简化成"给例子 + 扩展",在表格里比对话框更符合肌肉记忆;下次做数据处理类 AI 产品,先问自己:能不能挂列头/表头,不必套 chat。③ 「上下文域」将成为企业 AI 的新原语——Gemini 3.5 Pro 的分域上下文管理暗示:未来所有 AI 助手都要能说"我在这个文档的语境里回答"vs"我在整个 workspace 语境里回答";信息架构层要提前预留「上下文域切换器」的位置。双层开关矩阵三态:关 / 允许开 / 强制开(用 chip + 图标区分,不用色块);Fill with Gemini 挂列头右上小 icon(不占单元格);敏感字段"强制关闭"红标 = 8px 圆点 + tooltip 提示;分域上下文 chip:此文档 / 此表格 / 此对话 / 全 workspace,置于输入框上方;Gemini 3.5 Pro 灰度进度可见(不藏后台);管理员操作留操作 Log(Docs 域禁用 / 恢复的 audit trail)。

Microsoft 把 GPT-5.6 塞进 M365 Copilot 后,B 端 AI 控制台的两条产品设计原则又被再度证实:① 与其自造治理组件,不如直接对齐云厂商既有 UX 语言——Copilot 模型策略挂进 Admin Center 而不是新建"AI 控制台",让企业 IT 用"治理 Exchange 邮箱的经验"来治理 AI 模型,几乎零学习成本。② 「powered by」小 chip 是"双通道分发"的必要透明化——同一个 Copilot 底层可能是 GPT-5.6、Phi、Mistral,顶栏 12px chip 告诉用户"当前调用的是谁",既满足合规审计,又管理用户预期(某些国家/行业禁止使用美国模型)。"powered by GPT-5.6" chip 12px muted-soft 靠顶栏右侧;模型策略 = Azure AD 角色继承(List Row + 角色 chip);席位维度模型分配 = 二维矩阵(角色 × 档位);模型审计写入 M365 Compliance Center(而非独立 log);Copilot 顶栏永远可点 chip → 弹出"当前模型 · 策略来源 · 切换权限"三段信息。

OpenAI · Atlas Browser 关停 OpenAI 2026.07.12
  • Atlas 浏览器宣布 8 月 9 日停服（07.12）—— 上线不足一年即关停；OpenAI 官方原因是"用户核心 AI 需求已在 ChatGPT 主端与新桌面 App 中被覆盖"；数据迁移工具提供 4 周窗口，历史书签 / 阅读记录可导出为标准 HTML。
  • 关停通知策略 —— 首屏顶部固定 banner + 邮件 + 应用内 modal 三重提醒；modal 支持 "Later" 但保留每次启动重复提示；数据导出按钮永远在设置一级页可见，不藏。
  • 用户迁移路径 —— 官方推荐迁移到 Chrome / Safari + ChatGPT 桌面 App 组合；书签同步 ChatGPT Memory；「浏览历史 → 项目文件」一键转换到 ChatGPT Projects。
Atlas 关停不到一年是一个反面案例,能提炼三条产品设计原则:① 关停通知不能只依赖单一渠道——顶栏 banner + 邮件 + 应用内 modal 三重提醒是"给足用户走人时间"的礼貌;藏在博客里的关停公告 = 用户永远不知道 = 数据永远拿不回;这是产品对用户的最后一次尊重。② 数据迁移工具要永远在一级页面可见——不是"设置里翻三层才能找到导出按钮";关停期间用户情绪本就负面,再让他"找路"就是灾难;导出按钮应该像 "Save As" 一样显眼。③ 关停不是"扔掉"是"合流"——OpenAI 把 Atlas 用户导流到 ChatGPT 桌面 App + Projects,配合 Memory 同步、书签转项目,让"关停"从"你的数据没了"变成"你的资产搬家了";这条对做多产品线的公司最直接:内部产品线合并时,数据映射比"发关停公告"更能保住品牌信任。关停三重通知:顶栏 banner(不可关) + 邮件(3 次分批) + 首启 modal(每次可 Later);数据导出按钮 = 设置一级页固定位置 + 独立菜单条目;导出格式 = 标准 HTML + JSON(不用私有格式);迁移映射:书签 → Memory / 阅读历史 → Projects / 密码 → 系统钥匙串;stopping timeline = 首屏永久显示倒计时(D-28 → D-0);Later 按钮次数无上限但每次都提醒(减少焦虑)。

对我们的启示

从 07.09 ~ 07.15 这一周产品动态中提炼的 6 条具体、可执行的设计建议

Insight · 01
↗ ChatGPT Work / Sites · Enterprise 跨席位交接
长任务 Agent:先设计"打断态",再设计"执行态"
这周 Work、Sites、Enterprise 跨席位交接三条线共同把长任务 Agent 推到主线,共识非常明确:长任务 Agent 的核心不是"能跑多久",而是"能被中断吗"。用户在开会时按 Pause,回来再按 Approve/Reject,这才是真实工作流。产品该先设计好"暂停状态"的信息面(当前正在做什么 · 已经消耗多少 · 剩余步骤预估),再设计"执行状态"的动画。第二条:跨席位交接是企业场景的隐性需求——甲发起、乙审批、丙继续,状态机得原生支持授权流转,而不是"一个人一路点到底";单人视角设计出来的 Agent 一进企业就水土不服。Agent 五态:Running / Pause / Waiting for approval / Done / Error(比 4 态多一个 Pause);Pause 状态信息面 = 当前步骤 · 已消耗 · 剩余预估三行;跨席位交接 = 授权流转 UI(who / when / what 三栏抽屉);Approve / Reject 44pt 触控区 · 无限撤销时间轴;手机端 5 控件 · 桌面端全套 policy 编辑器。
Insight · 02
↗ ChatGPT Sites · Figma Design Snapshots 预告
AI 生成物要 URL:从"聊天里的一段文字"到"可分享资产"
Sites 让 AI 生成物挂上 chatgpt.com/sites/<slug> 是这一周最容易被忽视但影响最深远的变化。AI 生成物开始要 URL、要 og:image、要分享 sheet——不再是"聊天记录里可以复制的文字",而是可被搜索引擎索引、可发朋友圈、可挂进企业知识库的"一等公民资产"。做下一代 AI 产品要给生成产物预留三件套:URL slot、meta 面板(标题/描述/封面)、分享 sheet(权限:仅自己/组织/公开)。第二条:可分享资产必须内建"快照"机制——Figma Design Snapshots 预告告诉我们,一旦生成物有 URL,就必然需要"版本快照 + 一键回滚",否则 AI 改稿翻车时用户没法自救。生成物三件套:URL slot + og:image + 分享 sheet(权限三档:仅自己/组织/公开);slug 命名 = AI 建议 + 用户可改(先建议后编辑);快照 timeline 挂底栏 · hover 显示 diff · 单击回退 · 双击"回退+分支";meta 面板与生成物同层级(不藏在设置);企业级需追加"组织 slug 前缀"避免品牌混淆。
Insight · 03
↗ Fill with Gemini · admin/user 双层开关
数据密集场景:表单式 AI 优于对话式 AI
Fill with Gemini 把"提示 + 补全"两步换成"给示例 + 扩展",直接挂进列头——这是 B 端数据处理 AI 最值得抄的一条:凡是能用"给例子 + 扩展模式"完成的任务,不要再套一个 chat 对话框,直接把入口挂在列头 / 表头 / 单元格 hover。用户不需要"打招呼",不需要"描述任务",只需要"给一个例子";AI 归纳后一步预览、一步应用。第二条这周被再次实证:双层开关(admin/user)是企业 AI 治理最低标准——组织层管合规、个人层管心理安全,任何一层缺失都会引起投诉;做 B 端 AI 产品必须原生支持,不是"事后加一个开关"。Fill with Gemini 入口挂列头右上 icon(不套 chat);四步流程:示例 → 模式 → 预览 → 应用(每步可编辑);双层开关矩阵三态:关 / 允许开 / 强制开(chip + 图标不用色块);敏感字段"强制关闭"红标 = 8px 圆点 + tooltip 提示;user 层开关放"我的账户"首页(不藏在管理员设置);admin 操作留 audit trail。
Insight · 04
↗ Figma Dev Mode MCP Remote · Multiple AI edits
设计文件成为"AI 一等公民数据源",命名规范提前生产级化
Dev Mode MCP Remote 服务器化意味着工程师第一次可以在 IDE 里"@Figma"直接问 spec、token、变量、组件命名规则,而且无需再挂本地端口——LLM 会直接读你的组件树,命名不清 = AI 猜不对 = 交付错。设计侧要重新审视自己的:组件命名规范、变量命名规则、注释文字、状态命名(default / hover / active / disabled / loading),这些即将成为"AI 输入"而不只是"人类可读的组织"。第二条:AI 编辑必须支持"多任务后台"——设计师最反感"AI 独占画布"的等待感;把生成任务扔到后台、结果以卡片形式挂在侧栏,让设计师"边等边设计",这条对所有生成式设计工具都是必选项。组件命名规则 = 显式 lint 规则(AI 可读);变量层级 = 语义级 → token 级 → 值级(三层);状态命名统一:default / hover / active / focus / disabled / loading;多任务生成结果侧栏 = 状态四态(Running / Done / Review / Error);MCP 接入器 = IDE "@Figma" 命令(与 @file / @web 语法一致);组件注释支持 markdown(AI 直接摘要)。
Insight · 05
↗ OpenAI Atlas 关停 · Chat/Work/Codex 合并
产品线合并要留"回退旧版"的显式路径
Atlas 一年内关停 + Chat/Work/Codex 三线合并成新桌面 App,同一周发生两次"产品线剧变",给出的产品设计原则很硬:① 关停不是"扔掉"是"合流"——OpenAI 把 Atlas 用户导流到 ChatGPT 桌面 + Projects,配合 Memory 同步、书签转项目,让"关停"从"你的数据没了"变成"你的资产搬家了";这条对做多产品线的公司最直接。② 合并要留"回到 Classic"的显式路径——把三线收敛到一个入口是对的,但旧用户的心智不可能一夜切换,顶部或设置里保留一个 muted 的「回到 ChatGPT Classic」链接,是"我随时能走"的信任基础。③ 关停通知不能只依赖单一渠道——顶栏 banner + 邮件 + 应用内 modal 三重提醒,数据导出按钮永远在设置一级页可见,是产品对用户的最后一次尊重。关停三重通知:顶栏 banner(不可关) + 邮件(3 次分批) + 首启 modal(每次可 Later);数据导出永远在设置一级页固定位置(不藏);「回到 Classic」muted 链接放设置抽屉底部(非按钮);数据映射清单公开(书签 → Memory / 阅读历史 → Projects);stopping timeline 首屏永久倒计时;导出格式标准 HTML + JSON(不用私有格式)。
Insight · 06
↗ The Decoder OpenAI UX Crisis · Sidebar 回滚
发布节奏预算:一周不做 5 件大事,回滚是信任而非耻辱
OpenAI 这周把桌面合并、Work、Sites、GPT-5.6 GA、Plugin Directory 五件"C0 级"变更挤在同一天,即使每件都是好设计,叠在一起也让企业 IT 懵圈——The Decoder 报道后 OpenAI 紧急回滚 sidebar。这条教训对所有产品团队都直接:① 一次发布不要超过用户认知负载——"发布节奏预算"意识:一周最多 1 个"C0 级"变更(功能合并/新增付费档/定价变化),大改动要留 2~4 周的消化间隔。② 消耗透明是长任务 Agent 的最低门槛——用户不怕花钱,怕的是"不知道花了多少";长任务运行数小时,顶栏必须像行车电脑一样显示"当前速率 · 累计花费 · 预估总花费"。③ 官方回滚不是"失败",是"信任建立"——快速修正比死撑更值得客户尊敬;回滚公告首屏 banner + 明确注明"感谢反馈",不掩饰。发布节奏预算:一周最多 1 个 C0 级变更 + 2~4 周消化间隔;消耗 widget 三行:当前速率 · 累计花费 · 预估总花费(顶栏固定);Sidebar 密度上限 = 一屏可见项 ≤ 12(超过=折叠或分组);回滚公告 = 首屏 banner + "感谢反馈"文案(不掩饰);定价页横向对比列(每档列出典型任务耗时和成本);企业 IT 反馈通道置于顶栏(不藏)。
