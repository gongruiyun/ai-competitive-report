AI 消费级产品

Claude · ChatGPT · Gemini · Kimi · DeepSeek · MiniMax — UX 变化与功能发布

Claude Anthropic 2026.07.03 ~ 07.08
  • Claude Sonnet 5 登陆 AWS Bedrock（07.03）—— Anthropic 最强 Sonnet 通过 AWS 官方通道上架，主打编码 / 代理任务；企业客户可在现有 IAM / VPC / KMS 体系内直接调用，无需额外接入 Anthropic API 单独审计。
  • Claude apps gateway for AWS 发布（07.08）—— AWS 上线企业级统一网关，把 Claude Code、Claude Desktop 的访问、成本与策略聚合到单个控制面：可按团队分配 token 额度、可细粒度审计每次对话与工具调用、可禁止敏感场景使用；「AI 消费管控」正在成为企业标准工具箱。
Sonnet 5 通过 AWS 上架后，Claude 的桌面界面出现了两个可复用的产品设计原则：① 「模型来源」必须可见，不能默认收起——当同一款模型可以从 Anthropic 直购、也可以经 AWS 采购时，用户会误以为是两款不同模型；在模型选择器右侧显式标注"via AWS"这类小标签，比藏在设置里更能减少误判。② 消费透明化要前置到使用界面，而不是留给出账日——把「本团队本月余额」的进度条直接放在编辑器顶栏，让用户在写代码的时候就能感受到消耗节奏，是企业级 AI 工具的基础礼貌。具体位可参考：来源 chip = 12px muted-soft，紧贴 model picker 右侧；额度进度条颜色阶梯 <60%绿 / 60~85%琥珀 / >85%红；工具调用可展开右侧抽屉，input JSON / output JSON / duration 三段结构。
来源：anthropic.com/news · Sonnet 5 & Claude Code · AWS Blogs · Sonnet 5 & apps gateway
ChatGPT OpenAI 2026.07.07 前后
  • GPT-5.6 三档命名法进入更大预览范围（07.07）—— OpenAI 用 Sol（旗舰）/ Terra（平衡）/ Luna（轻量）替代传统「Ultra / Pro / Mini」，把「模型档位」从工程术语抽象成日常意象；CAISI（美商务部）审批完成后，Sol 首次向更大范围可信合作伙伴开放预览。
  • 政府 gating 常态化落地（07.07 前后）—— OpenAI 官方 Sol 预览页面明确：需在向可信合作伙伴发布 covered 模型前提供 CAISI 审核期。GPT-5.6 因此形成「预览 → 政府审批 → 更大预览」三段式节奏，「模型发布节奏」不再由产品经理独立决定。
GPT-5.6 三档命名的两个可复用设计原则：① 档位名字要走「意象」而非「工程量词」——Sol / Terra / Luna 三档比 Ultra / Pro / Mini 更容易让新用户在 3 秒内建立心智模型，因为「日光 / 大地 / 月亮」自带强弱层级和情绪色彩，不需要用户去猜"Pro 到底比 Ultra 强多少"。② 政府 gating 常态化之后，档位卡片需要一个「审批状态位」——被政府 gating 的档位不应该隐藏或直接置灰，而是保留可点、展示预计开放天数与「订阅通知」入口，让 IT 管理员始终知道自己能等到什么、什么时候能等到。具体位可参考：三档命名保持首字母大写 + 全小写显示；每档左上 12px 状态点（绿=已开放 / 琥珀=预审中含倒计时 / 灰锁=政府 gating）；档位图标共用 20px 网格，用形态区分而非色块，色弱友好。

ChatGPT Enterprise · Claude Enterprise · Gemini for Workspace — UX 变化与团队协作

企业级 AI 平台
Claude Enterprise · via AWS Anthropic × AWS 2026.07.03 ~ 07.08
  • Claude Sonnet 5 on AWS Bedrock（07.03）—— 企业客户可在 Bedrock 与 AWS Claude Platform 中直接调用 Sonnet 5，主打编码 + 代理任务；把「Anthropic 最强 Sonnet 」的接入方式统一到「云厂商既有权限体系」内，绕过额外的合规审批与账户对接。
  • Claude apps gateway for AWS（07.08）—— AWS 上线企业级统一网关，用来管控 Claude Code / Claude Desktop：按团队分配 token 额度、细粒度审计每次对话与工具调用、对敏感场景一键禁用；管理员不再依赖 Anthropic Console，而是从 AWS IAM 直接治理 Claude 消费。
  • 企业侧的行为改变 —— 「买 Claude」正式变为「向云厂商采购 Claude 服务」，与「向 Anthropic 直购」并行；两条采购通道让 Claude 的分发面从 SaaS 单点扩展成 SaaS + 云平台双通道。
Claude 从「向 Anthropic 直购」进入「SaaS + 云平台双通道」后，企业界面得学两条产品设计原则：① 用户此刻属于哪个组织实例必须一目了然——同一个员工可能同时被拉进 Anthropic 直购和 AWS 采购两个组织，顶栏必须永远告诉他"你现在在哪儿"，否则会话数据、权限、消费归属都会混乱。② 双通道意味着不能锁死切换路径——设置底部要保留一个 muted 的「切回另一通道」链接，即使 99% 的用户不会用，也是"你随时能走"的心理安全感；企业 IT 尤其对此敏感。具体位可参考：顶栏「Org · AWS-XXXX」12px muted-soft chip；工具调用行右侧 hover 出 Popover（不用 Modal）显示 input JSON / output JSON / duration；「一键切回 Anthropic 直购」muted 链接放在设置抽屉底部。
来源：anthropic.com/news · Enterprise 双通道 · AWS Blogs · apps gateway
ChatGPT Enterprise / Edu OpenAI 2026.07.07 前后
  • GPT-5.6 三档命名法 Enterprise 落地（07.07）—— Enterprise 席位将首批获得 Sol / Terra / Luna 三档；企业管理员可通过 Reasoning Model Access / Pro Model Access 分别控制哪些席位可用最高档，隐藏用户无权限使用的档位。
  • CAISI 审批完成 → 企业侧首批解锁（07.07 前后）—— OpenAI 官方 Sol 预览页说明：covered 模型在向可信合作伙伴发布前需完成 CAISI 审核期；Enterprise 客户成为最早的合规验证对象。「AI 采购」从纯技术评估进化为「安全 / 合规双轨审批」。
政府 gating 常态化之后，Enterprise 版控制台需要提前预留两个位置：① 「角色 × 档位」的可组合权限，不再是「席位 = 档位」硬绑定——普通员工 / VIP / 研究员在同一个工作区里能用不同档，管理员配置成本大幅降低；组件形态应该是 List Row + 复选框而不是下拉，因为选择不是互斥的。② 「本工作区能力清单」需要显式展示每项能力的合规状态——不能只在"用户点击才失败"时才告诉他"这个不能用"，而是设置抽屉里就有一份能力总览，标注绿 / 琥珀 / 灰锁，让管理员可预期。具体位可参考：Reasoning Model Access / Pro Model Access 双开关走 List Row 形态；能力清单每行状态点尺寸 8~10px，倒计时天数用 tabular-nums 排版避免抖动；灰锁档保留「订阅通知」入口，不做完全隐藏。
来源：openai.com · GPT-5.6 Sol Preview

云厂商 AI 平台

AWS Bedrock · Azure AI · Google Cloud — 企业控制台 UX 更新

AWS · Bedrock & apps gateway Amazon Web Services 2026.07.03 ~ 07.08
  • Claude Sonnet 5 通过 Bedrock 上架（07.03）—— AWS 把 Anthropic 最新 Sonnet 直接纳入 Bedrock 模型目录，企业无需额外账号即可使用；对 AWS 客户而言，「模型选型」变成 Bedrock 控制台里一个选择器动作，且计费与既有 AWS 账单合流。
  • Claude apps gateway for AWS 发布（07.08）—— 一个专用网关把 Claude Code / Desktop 的访问、成本与策略聚合起来；配套 CloudWatch 指标与 IAM 精细化权限，直接对齐 AWS 客户熟悉的运维语言。
  • 企业管控 UX 的 AWS 化—— 「AI 应用消费」被切齐到 AWS 通用治理模式（IAM 权限 + CloudTrail 审计 + Budgets 预算 + Service Quotas 配额）；企业管理员用「治理 EC2 / S3 的经验」来治理 Claude。
B 端 AI 控制台的两条产品设计原则，直接决定采购摩擦系数：① 与其自造治理组件，不如直接对齐云厂商已有的 UX 语言——权限用 AWS 的 IAM Row 而不是自己发明"角色矩阵"、审计用 CloudTrail Log Table 而不是自制审计视图；每个 AWS 老员工都懂这套，学习成本几乎为零，销售就少一段"教学话术"。② 治理组件的路径要延续既有习惯——例如「申请提额」应该直接跳工单流，而不是让管理员在后台改数字；「超预算」应该发 SNS 通知而不是发邮件——这不是技术选择，是"和企业客户的既有工作流合流"。对照表：权限 = IAM Row（principal + action + resource 三列）；审计 = CloudTrail Log Table（时间 · 用户 · 操作 · 资源四列 + 详情抽屉）；预算 = Budgets Chart（柱状 + 红/琥珀/绿阈值线）；配额 = Service Quotas Row + 「申请提额」跳工单按钮。

对我们的启示

从本期产品动态中提炼的 6 条具体、可执行的设计建议

Insight · 01
↗ OpenAI · GPT-5.6 Sol / Terra / Luna
模型档位从「工程量词」进化为「意象词表」
这一周最能拿来直接对齐的启示：档位名字要走意象，不要走量词。Sol / Terra / Luna 比 Ultra / Pro / Mini 好在让新用户 3 秒内就有心智模型——「日光/大地/月亮」自带强弱层级，不需要用户去查手册"Pro 到底比 Ultra 强多少"。第二条：政府 gating 常态化以后，档位卡片必须留一个「审批状态位」——被 gating 的档位不隐藏、不置灰，而是保留可点、告诉用户"预计 X 天后开放"，让企业 IT 觉得"可预期"而非"看不到"。词表首字母大写 + 全小写显示；每档左上 12px 状态点（绿=已开放 / 琥珀=预审中含倒计时 / 灰锁=政府 gating）；档位图标 20px 网格 · 靠形态而非色块区分（色弱友好）。
Insight · 02
↗ AWS · Bedrock & apps gateway
B 端 AI 控制台，别自造轮子对齐云厂商语言就够了
做 B 端 AI 控制台时最容易走偏的一步：花几个月自造"角色矩阵""审计视图""预算面板"。更好的路径是直接对齐云厂商已经有的 UX 语言——权限用 IAM Row、审计用 CloudTrail Log Table、预算用 Budgets Chart、配额用 Service Quotas Row。每个 AWS 老员工都懂这套，销售就少一段"这是什么"的教学话术，采购摩擦系数直接降一半。第二条："申请提额"这类高频动作要延续云厂商既有工作流——直接跳工单流，而不是让管理员在后台改数字。4 组对照可直接落到设计规范：权限 = IAM Row（principal + action + resource）· 审计 = 时间 · 用户 · 操作 · 资源四列 + 详情抽屉 · 预算 = 柱状 + 红/琥珀/绿阈值线 · 配额 = 团队 token 上限 + 跳工单按钮。
Insight · 03
↗ Anthropic × AWS · 双通道分发
同一个 AI 产品在双通道下要显式声明"你现在在哪儿"
当 AI 产品从「SaaS 单点」扩到「SaaS + 云平台双通道」，最容易被忽视但代价最大的一件事：员工可能同时属于两个组织实例，界面必须显式告诉他"你现在在哪儿"。数据、权限、消费归属都挂在这里，藏在设置里的 org 切换器不够，顶栏得永远留一个身份 chip。第二条：双通道意味着不能锁死切换路径——设置底部要保留一个 muted 的"切回另一通道"链接，即使 99% 的用户不会用，也给出"你随时能走"的心理安全感；企业 IT 尤其对此敏感。顶栏「Org · AWS-XXXX」12px muted-soft chip；model picker 右侧 "via AWS" 来源标签；Claude Code 侧栏底部团队 token 余额进度条 <60%绿 / 60~85%琥珀 / >85%红；「一键切回 Anthropic 直购」muted 链接放设置抽屉底部。
Insight · 04
↗ Meta · Muse Image in IG / WhatsApp
AI 越"隐入"越好，但产物必须留一条可溯源的尾巴
Muse 把生图能力塞进「输入框旁的一个 icon」——不做独立 App、不占 tab、不抢焦点，让 AI 变成"消息装饰"而不是"新产品"。这是消费级 AI 目前跑得通的一条路:低依赖场景不需要独立 IA，隐入既有输入器就够了。但隐入必须有代价——生成物要留一条可溯源的视觉尾巴:右下一个轻水印、长按出"AI 生成 · 可举报"的 sheet，把「谁在生成、生成给谁」讲清楚，才不会被平台策略反噬。设计侧要谨慎的一点:不要把这个入口做成 FAB 那种"主功能"的份量，它就是一个 24px 的按钮。入口 = 24px icon 挂在输入框右侧（不是 FAB）；生成中 = 消息气泡渐变霓虹描边；生成物右下 8px、不透明度 10% 的水印；长按弹 sheet 三选项「重生成 / 换风格 / 举报」。
Insight · 05
↗ OpenAI · CAISI 政府审批常态化
合规状态：企业 AI 控制台里不该缺席的一列
CAISI 审批把「政府 gating」从个案变成了常态：企业选型 AI 模型时，「合规状态」不再是法务合同附件，而是产品里的一列数据。这意味着 B 端 AI 控制台的模型列表、档位卡片、路由页要开始留合规位——像 IAM 里的「MFA 是否开启」那样，作为一个可排序、可过滤的字段暴露出来。第二条:合规是一个「状态机」，不是布尔值——一个模型可能同时处于「已通过 CAISI / 待欧盟 AI Act / 政企租户不可用」，需要用 chip 组合展示，而不是一个「合规 ✓」了事；hover 抽屉展开完整审批清单。模型行右侧留 32px 合规列 · chip 组合形态: 绿"CAISI ✓" · 琥珀"EU AI Act 待审" · 灰"政企租户不可用" · 列表表头可按合规状态排序;hover 抽屉展开完整审批时间线。
Insight · 06
↗ Figma · Config 2026 后静默扩容期
大版本发完之后,主动进入"什么都不出"的观察期
Config 2026 之后 Figma 整整一周没上新功能——这不是没做,而是有意识的「静默扩容期」:大版本发完后, 30~60 天内产品团队应该主动不发新东西, 用来吸收上一波变更的反馈、修 bug、稳定文档、跑 A/B。这一条对内部团队很重要:我们经常在大版本上线次周就急着排下一个 flag,导致用户「上周才学会的东西这周又变了」。第二条:「静默」不等于「消失」——需要在 changelog、Discord、社区透出"这周在做什么",比如"AI Actions 使用数据看板正在 dogfood",让用户知道产品没停,只是没塞给他新按钮。changelog 分两栏:"本周发布"（可空） + "本周观察"（内部数据/未上线原型）; 官网首页顶栏 chip "Stabilizing v2026.7 · Day 5 / 30";用户端只看到 muted 一句"本周专注质量,无新功能上线"。
