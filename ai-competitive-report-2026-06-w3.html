AI 消费级产品

Claude · ChatGPT · Gemini · Kimi · DeepSeek · MiniMax — UX 变化与功能发布

Claude Anthropic 2026.06.30 ~ 07.08
  • Claude Sonnet 5 首发（06.30）—— 1M token 上下文；引入 Effort Control：用户手动选择「更快」或「更深思考」，在成本与性能间自主平衡；引入价 $2/$10 每百万 token 保持至 8/31，之后恢复 $3/$15。Free / Pro 首日即默认使用；Max / Team / Enterprise 同步开启。
  • Fable 5 / Mythos 5 重新部署（06.30）—— 美国政府批准后 Anthropic 恢复顶级模型访问；改进的安全分类器阻断 99% 借由 jailbreak 生成漏洞利用代码的行为；与 Amazon / Microsoft / Google 共同发布行业级 Jailbreak Severity Framework。
  • Claude Science 独立 App（06.30）—— 面向制药与生命科学研究的垂直 AI Workbench；PubMed 检索、Jupyter Notebook、R 会话、HPC 集群终端合并到单一界面；60+ 预配置科研 skill；协调 Agent + reviewer Agent 双 Agent 架构自动校验计算与引用；原生渲染 3D 蛋白结构。
  • Sonnet 5 登陆 AWS Bedrock（07.03）—— 通过 AWS 通道上架 Bedrock 与 AWS Claude Platform；企业客户在既有 IAM / VPC / KMS 体系内直接调用，无需额外接入 Anthropic API。同一款模型出现两条采购通道。
  • Claude apps gateway for AWS（07.08）—— AWS 上线企业级统一网关，把 Claude Code / Claude Desktop 的访问、成本与策略聚合到一个控制面；管理员可按团队分配 token 额度、细粒度审计每次对话与工具调用、对敏感场景一键禁用。「AI 消费管控」正在成为企业标准工具箱。
双周合幰后 Claude 给出三条可复用的产品设计原则:① 高专业度垂直场景要独立成 workbench,不是塞回主 app——Science 独立 App 的组件库、导航、审计路径与通用 chat 完全不一样,共用一个信息架构反而拧巴。② 双通道分发下"模型来源"必须可见——当 Sonnet 5 既能从 Anthropic 直购、也能经 AWS Bedrock 采购,用户会误以为是两款不同模型;在 model picker 右侧标注"via AWS"这类小 chip,比藏在设置里更能减少误判。③ 消费透明化前置到使用界面,不留给出账日——把「本团队本月余额」进度条直接放在编辑器顶栏,让用户在写代码时就能感受到消耗节奏,是企业级 AI 工具的基础礼貌。Effort Control 用 chip 而非 slider(连续区间→离散两态);Science 三栏 workbench(资源/画布/上下文);来源 chip 12px muted-soft 紧贴 model picker 右侧;额度进度条阶梯 <60%绿 / 60~85%琥珀 / >85%红;工具调用抽屉三段结构(input JSON / output JSON / duration)。
来源：anthropic.com/news · Sonnet 5 & Science & Fable 5 · AWS Blogs · apps gateway
ChatGPT OpenAI 2026.06.25 ~ 07.07
  • Codex Remote GA（06.25）—— 手机 App 启动 / 审批远程 Mac 或 Windows 上的编码任务；QR 一对一配对建立可信通道；登出即断开 Remote Control，配对不丢失。Agent 的「监督界面」正式向移动端迁移。
  • Memory 全面重构（06.25，Enterprise 起）—— 个性化回答下新增 Sources 面板，显示引用的记忆 / 历史对话 / 自定义指令；用户可修改内容、删除引用、标记为不相关或一键回退到旧版 Saved memories。
  • 模型选择器简化（06.26）—— 6 档：Instant / Medium / High / Extra High / Pro Standard / Pro Extended；Thinking Light 下线；Instant 可自动切换到 Medium。选项决策从「选模型」变为「选努力度」。
  • Personal Finance 扩展（06.26）—— Plus 用户可用（美国 web + iOS），Pro/Plus Android 端也开放；连接账户后建立仪表盘并支持上下文提问。
  • GPT-5.6 Sol / Terra / Luna 首预览（07.07）—— OpenAI 用 Sol（旗舰）/ Terra（平衡）/ Luna（轻量）三档意象化命名替代传统「Ultra / Pro / Mini」；CAISI（美商务部）审批完成后，Sol 首次向更大范围可信合作伙伴开放预览。「模型档位」从工程术语走向日常意象；「模型发布节奏」不再由产品经理独立决定。
双周合幰后 ChatGPT 端上有三条最直接的启示:① AI 输出不该默认都长成"气泡消息"——Personal Finance 用仪表盘、Memory 用 Popover 面板、Codex 用状态卡片,同一个模型四五种输出形态,靠"内容类型 → 组件类型"的映射决定容器,而不是全都塞进对话框。② 企业级模型选择器要"隐藏"而不是"置灰"——看得到用不了会让企业 IT 觉得"你在推销",隐藏则给 IT 完整的治理感。③ 政府 gating 常态化以后,档位卡片必须留一个"审批状态位"——被 gating 的档位不隐藏、不置灰,而是保留可点、告诉用户"预计 X 天后开放",让企业 IT 觉得"可预期"。Codex Remote QR 配对(移动端信任建立最小交互);Memory Sources 用 Popover 而非 Modal;6 档 picker 无权限档「隐藏 vs 置灰」;三档命名 Sol/Terra/Luna 首字母大写 + 全小写显示;档位左上 12px 状态点(绿=已开放 / 琥珀=预审中含倒计时 / 灰锁=政府 gating);档位图标 20px 网格 靠形态而非色块区分。

Gemini Google 2026.06.25 ~ 07.01
  • Gemini Study Notebooks 上线（06.25）—— 学生上传学习材料 → Gemini 生成诊断测试 + 定制课程 + 阶段测验 + 进度仪表盘；与 NotebookLM 双向共享资料，形成「学 → 测 → 复习」闭环。生成式 AI 首次以「学习路径」而非「回答」为交付物。
  • Gemini Business Notebooks 上线（07.01）—— 直连 Google Business Profile；一键连接后 Gemini 主动扫描并推送「未回复评论 / 未设节假日营业时间 / 定价优化点」等待办建议。SMB 老板可在 Gemini 中直接生成品牌口吻的评论回复。
Study Notebooks 和 Business Notebooks 是同一个模型两套人设,证明B 端 AI 助手的差异不在模型,而在文案主导权和主动推送节奏。这一周最有共识价值的一条:「主动推送 3~5 张待办卡片」正在成为 B 端 AI 的默认首屏,反转了过去"先输入后输出"的老默认——AI 从"等你问"变成"先告诉你 3 件该做的事"。第二条:Notebooks 三栏工作台(左资源 / 中生成路径 / 右上下文)是数据密集型 AI 的模板 IA,当你要处理"多源资料 → 生成结构化产出"时,三栏结构比 chat + 侧栏更清晰,做自家的 dashboard、AI PM 助手前先按这个骨架搭。首屏 3~5 张待办卡片(反转 chat 默认);三栏 IA:资源列 / 生成路径主区 / 上下文抽屉;场景语气差异靠 tone token,不靠换模型;待办卡片 = 12px 场景 icon + 14px 标题 + 单 CTA。
来源：blog.google · Gemini Study & Business Notebooks

ChatGPT Enterprise · Claude Enterprise · Gemini for Workspace — UX 变化与团队协作

企业级 AI 平台
Claude Enterprise · via AWS Anthropic × AWS 2026.06.30 ~ 07.08
  • Claude Science 面向企业发布（06.30）—— 生命科学垂直 AI Workbench；PubMed / Jupyter / R / HPC 集成到单一界面；Actor-Critic 双 Agent 架构校验计算与引用；Pro / Max / Team / Enterprise 均可开通 beta。
  • Jailbreak Severity Framework（06.30）—— 与 Amazon / Microsoft / Google 共建的行业级安全分级标准同步落地企业席位，为 IT 管理员提供跨厂商一致的越狱严重度评估口径。
  • Sonnet 5 on AWS Bedrock（07.03）—— 企业客户可在 Bedrock 与 AWS Claude Platform 直接调用 Sonnet 5，主打编码 + 代理任务；把「Anthropic 最强 Sonnet」的接入方式统一到「云厂商既有权限体系」内，绕过额外的合规审批与账户对接。
  • Claude apps gateway for AWS（07.08）—— AWS 上线企业级统一网关，用来管控 Claude Code / Claude Desktop：按团队分配 token 额度、细粒度审计每次对话与工具调用、对敏感场景一键禁用；管理员不再依赖 Anthropic Console，而是从 AWS IAM 直接治理 Claude 消费。
  • 企业侧的行为改变 —— 「买 Claude」正式变为「向云厂商采购 Claude 服务」，与「向 Anthropic 直购」并行；Claude 分发面从 SaaS 单点扩展成 SaaS + 云平台双通道。
Claude 从「向 Anthropic 直购」进入「SaaS + 云平台双通道」后,企业界面得学两条产品设计原则:① 用户此刻属于哪个组织实例必须一目了然——同一员工可能同时被拉进 Anthropic 直购和 AWS 采购两个组织,顶栏必须永远告诉他"你现在在哪儿",否则会话数据、权限、消费归属都会混乱。② 双通道意味着不能锁死切换路径——设置底部要保留一个 muted 的「切回另一通道」链接,即使 99% 的用户不会用,也是"你随时能走"的心理安全感;企业 IT 尤其对此敏感。第三条:Reviewer 卡三态是"高专业度 workbench"的信任建设标配——Actor-Critic 双 Agent 把每次计算和引用都挂一张"已复核 / 疑问 / 未复核"reviewer 卡,做金融、法务、医药这类严肃场景时可以直接抄。顶栏「Org · AWS-XXXX」12px muted-soft chip;工具调用行右侧 hover 出 Popover(不用 Modal);「一键切回 Anthropic 直购」muted 链接放设置抽屉底部;Reviewer 卡三态(已复核绿/疑问琥珀/未复核灰);Science 三栏 workbench + ⌘K 场景分组面板(替代 60+ 按钮墙)。
来源：anthropic.com/news · Sonnet 5 & Science & Enterprise 双通道 · AWS Blogs · apps gateway
ChatGPT Enterprise / Edu / Business OpenAI 2026.06.25 ~ 07.07
  • 可视化 Memory + Sources 面板（06.25）—— 个性化回答下方标注引用来源；用户可点击每条 memory / 历史对话查看原文、修改、删除或标记为不相关，也可一键退回到旧版 Saved memories。企业版首推 2 周 early access，之后默认打开。
  • Plugin 管理进驻 Workspace 设置（06.25）—— 管理员可按角色、状态、类别搜索并配置插件；可强制默认安装或限定可安装范围，「AI 生态治理」终于有了一站式界面。
  • 模型选择器统一简化（06.26）—— Enterprise / Edu 与消费级同步使用 6 档；Reasoning Model Access / Pro Model Access 两个开关分别控制思考模型与 Pro 模型的可用性，隐藏用户无权限使用的档位。
  • GPT-5.6 三档命名 Enterprise 落地（07.07）—— Enterprise 席位将首批获得 Sol / Terra / Luna；企业管理员可通过 Reasoning / Pro Model Access 分别控制哪些席位可用最高档，隐藏用户无权限使用的档位。
  • CAISI 审批完成 → 企业侧首批解锁（07.07）—— OpenAI 官方 Sol 预览页说明:covered 模型在向可信合作伙伴发布前需完成 CAISI 审核期；Enterprise 客户成为最早的合规验证对象。「AI 采购」从纯技术评估进化为「安全 / 合规双轨审批」。
双周合幰后企业级 ChatGPT 有三条设计原则:① 企业级 AI 产品的核心不是"更多设置",而是设置的可组合性——Sources 的审计视图、Plugin 的双开关、权限档的隐藏机制,每一个都不是"新按钮",而是可组合成不同角色配置的"设置原子"。② 企业级审计不能只显示"引用了什么",还得显示"谁在什么时间怎么改的"——Sources 面板的 timestamp / 编辑者 / 权限来源三列是 SOC 2 / ISO 27001 合规审查的最低要求。③ 政府 gating 常态化以后,「角色 × 档位」是可组合权限,不再"席位 = 档位"硬绑定——普通员工 / VIP / 研究员在同一个工作区里能用不同档,组件形态应该是 List Row + 复选框而不是下拉。Sources 审计三列:timestamp / 编辑者 / 权限来源;Plugin 双开关(Allow + Push);模型档「隐藏而非置灰」;Reasoning / Pro Model Access 走 List Row 形态;能力清单每行状态点 8~10px;倒计时天数用 tabular-nums 排版;灰锁档保留「订阅通知」入口。

Gemini for Workspace Google 2026.06.25 ~ 07.01
  • Study Notebooks 面向教育版（06.25）—— Workspace for Education 用户可在 Gemini 中把课程材料一键生成为诊断测试、阶段性测验和进度仪表盘，与 NotebookLM 双向共享上下文。
  • Business Notebooks 直连 Google Business Profile（07.01）—— 中小企业管理员可在 Gemini 中直接查询商家数据（曝光、导航、通话、客户互动），并让 Gemini 生成品牌口吻的评论回复。
Gemini for Workspace 打了个样:B 端 AI 助手的默认状态不该是空对话框,而是"已经帮你想好了 3 件事"的待办清单——OAuth 一完成就在首屏浮出建议,不等用户提问。这一步反过来说明过去 5 年做 SaaS AI 的默认状态"输入你想问什么"是懒惰的产品设计,把工作推给了用户。第二条:主动内容必须带"品牌口吻"参数——通用 AI 文案配上商家专属人设会立刻违和,评论回复、SMS 草稿、邮件模板都要在设置里给出「公司名 + 语气 + 禁词」三档,写进 prompt 而不是让用户手改。OAuth 后主动扫描 → 首屏 3 张待办卡;CTA 用「生成」而非「查看」(降一次点击);Tone token:公司名 / 语气(正式/亲切) / 禁词表 三档;建议卡片一次不超过 5 张(防溢出)。

云厂商 AI 平台

AWS Bedrock · Azure AI · Google Cloud — 企业控制台 UX 更新

AWS · Bedrock & apps gateway Amazon Web Services 2026.07.03 ~ 07.08
  • Claude Sonnet 5 通过 Bedrock 上架（07.03）—— AWS 把 Anthropic 最新 Sonnet 直接纳入 Bedrock 模型目录，企业无需额外账号即可使用；对 AWS 客户而言，「模型选型」变成 Bedrock 控制台里一个选择器动作，且计费与既有 AWS 账单合流。
  • Claude apps gateway for AWS 发布（07.08）—— 一个专用网关把 Claude Code / Desktop 的访问、成本与策略聚合起来；配套 CloudWatch 指标与 IAM 精细化权限，直接对齐 AWS 客户熟悉的运维语言。
  • 企业管控 UX 的 AWS 化 —— 「AI 应用消费」被切齐到 AWS 通用治理模式(IAM 权限 + CloudTrail 审计 + Budgets 预算 + Service Quotas 配额);企业管理员用「治理 EC2 / S3 的经验」来治理 Claude。
B 端 AI 控制台的两条产品设计原则,直接决定采购摩擦系数:① 与其自造治理组件,不如直接对齐云厂商已有的 UX 语言——权限用 AWS 的 IAM Row 而不是自己发明"角色矩阵"、审计用 CloudTrail Log Table 而不是自制审计视图;每个 AWS 老员工都懂这套,学习成本几乎为零,销售就少一段"教学话术"。② 治理组件的路径要延续既有习惯——「申请提额」直接跳工单流,不让管理员在后台改数字;「超预算」发 SNS 通知不发邮件——这不是技术选择,是"和企业客户的既有工作流合流"。对照表:权限 = IAM Row(principal + action + resource 三列);审计 = CloudTrail Log Table(时间 · 用户 · 操作 · 资源四列 + 详情抽屉);预算 = Budgets Chart(柱状 + 红/琥珀/绿阈值线);配额 = Service Quotas Row + 「申请提额」跳工单按钮。

  • Motion / 3D transforms / Shaders 进入画布 —— Motion 时间轴动画由 Figma agent 生成并交付「dev-ready」代码；3D transforms 让静态设计具备立体感；Shaders 通过 prompt 描述纹理效果并可分享复用。设计师不再需要跳出 Figma 完成动效与材质。

  • Figma Weave 深度整合 —— 收购后的 Weave workflow 可在 Figma 内直接创建、发布为工具或模板，并可分享到 Figma Community。
Config 2026 之后的一条底层启示:画布不再只是"像素稿",而是多态资产容器。Motion / 3D / Shader / Code 与 Static 并列存在于同一张画布,意味着设计文件从"帧的集合"变成了"资产类型的集合"——下次我们做资产库、组件库、DAM 类产品时,分类维度应该是"资产类型",而不是"文件夹层级"。第二条:Agent Skill 需要按「我的 / 团队 / 组织」三档共享,而不是简单的 prompt 收藏夹——技能可见范围决定了它是不是能被复用,团队级 skill 库是"AI 助手规模化"的必选项,粒度比 prompt 收藏夹深一级。资产类型 chip:Motion / 3D / Shader / Code / Static 图层顶栏并列;Code Layer 双向绑定 Git commit hash("设计已过期"提示);Agent Skill 三档共享:我的 / 团队 / 组织;Motion 用 timeline 时间轴,不用 hover 状态描述。

AI 原生入口

Meta · Notion · Microsoft — 用户直接接触 AI 的新界面

Meta · Muse Image Meta 2026.07.07
  • Muse Image 发布并内嵌至 Instagram / WhatsApp —— 用户可在私信、故事流、Reels 编辑器内直接生成图像，无需切换到独立生成器；生成式 AI 变成「即时消息中的一个按钮」。
  • 「AI 作为交互控件」而非「AI 作为独立产品」 —— Meta 的策略是让 AI 消隐在最贴身的日常场景里，用户不必知道自己在「用 AI」；发送按钮旁的一个 icon 就是完整入口。
Meta 把 AI「消隐进消息流」的两条产品设计原则:① AI 触发点越小越安静越好,不要新增顶栏或 tab——一个输入框旁边的星芒 icon 比在导航加"AI 助手"入口更符合"隐入按钮"策略;用户不需要意识到自己在用 AI,AI 就应该像发送键一样是"自然的"。② 隐入的代价是必须保留可溯源——每张生成图右下角固定的低透水印是必要的,即便看起来很轻,也让整个产物在被转发、被截图、被误认为"真实照片"的时候不至于失控。设计侧要谨慎:不要把这个入口做成 FAB 那种"主功能"的份量,它就是一个 24px 的按钮。AI 触发键 24px 星芒 icon 放在输入框右侧(+ 号旁,不做 FAB);生成中态用消息气泡"渐变霓虹描边"表示进行,避免打断聊天流;水印规格 8px 字号 · 10% 透明度 · 固定右下角;长按弹 sheet 三选项「重生成 / 换风格 / 举报」。

对我们的启示

从 06.25 ~ 07.08 双周产品动态中提炼的 6 条具体、可执行的设计建议

Insight · 01
↗ Figma · Config 2026(Motion / 3D / Shaders / Code Layers)
画布进入"多态资产容器"时代,分类维度改用"资产类型"
Config 2026 之后要更新的一个心智:画布不再是"帧的集合",而是"资产类型的集合"。Motion / 3D / Shader / Code 和 Static 层平级——每种类型都有自己的编辑面板、评审流程和交付物。做自家的资产库/DAM/组件库,把顶层分类从"文件夹"改成"资产类型 chip",能一下解决交付物混乱、命名混乱、评审路径混乱三个老问题。第二条:Shader 层的交付物是 prompt 字符串,不是贴图文件——这条对做 AIGC 素材管理的团队最直接:资产库里要给"prompt 类资产"留一个专属版本管理路径,不能当普通图片管。图层顶栏 5 个资产类型 chip;Motion 用 timeline 时间轴描述,不用 hover 状态;3D 引入 Z 轴 = 层级(不再等价 z-index);Shader 层交付物 = prompt 字符串。
Insight · 02
↗ ChatGPT · Codex Remote GA · Claude Code
Agent 型工具:桌面写策略,手机做审批
Codex Remote 与 Claude Code 这一双周把 Agent 型工具的界面语言拉齐:Agent 型工具的移动端不需要复刻桌面版。桌面端负责"写 policy、看 diff、调 log";移动端只负责"通勤路上一按 Approve",两个端做的是不同的事,不是同一件事的不同尺寸。第二条:Agent 状态就四种,别发明第五种——Running / Waiting for approval / Done / Error 已经是行业共识,任何"半成品/挂起/审核中"都能塞进这四态,自造术语只会让集成方懵圈;手机端 5 个控件就够——标题、状态 chip、Approve、Reject、Pause,多一个都会让用户在通勤地铁上误触。状态 chip 四态:Running / Waiting / Done / Error(8px 圆点前缀);Approve / Reject 44pt 触控区;耗时用数字优于百分比条;展开原文默认收起;Effort Control 档位≤3(超过=暴露参数)。
Insight · 03
↗ ChatGPT · 6 档模型选择器 + GPT-5.6 Sol / Terra / Luna
模型档位命名:量词 → 意象词表,并给"审批状态位"留一格
双周里 OpenAI 把「模型档位」推进了两步。第一步 6 档命名给出三条可对照的避坑准则:不用"Fast"用"Instant"(速度是结果不是承诺)、不用"Better/Best"用"Medium/High/Extra High"(避免价值判断陷阱)、付费档用统一前缀"Pro Standard / Pro Extended"(一眼分辨免费/付费边界)。第二步 Sol / Terra / Luna 更进一步:档位名字要走"意象"而非"工程量词"——「日光/大地/月亮」自带强弱层级和情绪色彩,新用户 3 秒建心智,不用查手册。CAISI 政府 gating 常态化后,档位卡片必须留一个「审批状态位」:被 gating 的档不隐藏、不置灰,而是保留可点、告诉用户"预计 X 天后开放"。Instant · Medium / High / Extra High · Pro Standard / Pro Extended(避免 Fast / Better);意象命名首字母大写 + 全小写显示;档位左上 12px 状态点(绿=已开放 / 琥珀=预审中含倒计时 / 灰锁=政府 gating);档位图标 20px 网格 · 靠形态而非色块区分(色弱友好);企业无权限档隐藏而非置灰。
Insight · 04
↗ Anthropic × AWS · Claude 双通道分发
同一个 AI 产品在双通道下要显式声明"你现在在哪儿"
当 AI 产品从「SaaS 单点」扩到「SaaS + 云平台双通道」,最容易被忽视但代价最大的一件事:员工可能同时属于两个组织实例,界面必须显式告诉他"你现在在哪儿"。数据、权限、消费归属都挂在这里——藏在设置里的 org 切换器不够,顶栏得永远留一个身份 chip。第二条:双通道意味着不能锁死切换路径——设置底部保留一个 muted 的"切回另一通道"链接,即使 99% 的用户不会用,也给出"你随时能走"的心理安全感;企业 IT 尤其对此敏感。这条同样适用于任何要跨云、跨代理商、跨采购通道分发的 SaaS 产品。顶栏「Org · AWS-XXXX」12px muted-soft chip;model picker 右侧 "via AWS" 来源标签;团队 token 余额进度条 <60%绿 / 60~85%琥珀 / >85%红,置于编辑器顶栏;「一键切回原通道」muted 链接放设置抽屉底部。
Insight · 05
↗ Meta · Muse Image in IG / WhatsApp
AI 越"隐入"越好,但产物必须留一条可溯源的尾巴
Muse 把生图能力塞进「输入框旁的一个 icon」——不做独立 App、不占 tab、不抢焦点,让 AI 变成"消息装饰"而不是"新产品"。这是消费级 AI 目前跑得通的一条路:低依赖场景不需要独立 IA,隐入既有输入器就够了。但隐入必须有代价——生成物要留一条可溯源的视觉尾巴:右下一个轻水印、长按出"AI 生成 · 可举报"的 sheet,把「谁在生成、生成给谁」讲清楚,才不会被平台策略反噬。设计侧要谨慎:不要把入口做成 FAB 那种"主功能"的份量,它就是一个 24px 的按钮。入口 = 24px icon 挂在输入框右侧(不是 FAB);生成中态 = 消息气泡渐变霓虹描边(不打断聊天流);生成物右下 8px、10% 透明度水印;长按弹 sheet 三选项「重生成 / 换风格 / 举报」。
Insight · 06
↗ Claude Science · via AWS + Gemini Study / Business Notebooks
先分清「聊天窗口」还是「工作台」,组件库根本不同
当 PM 说"给这个功能加个 AI",先要问一句:它是聊天窗口,还是工作台? 两者的组件库、输入形态、输出容器、持久化机制、校验流程——五个层面全都不一样,不能靠"共用一套组件加点判断"糊过去。双周内 Claude Science、Gemini Notebooks 都把这条边界画得非常清楚:垂直场景 → Workbench,通用问答 → Chat。第二条:Workbench 的输出必须是"可编辑资产",不是"气泡消息"——Notebook cell、3D 视图、表格、报告页面,任何 AI 生成的东西都要能被继续修改,不能只提供一个"复制"按钮让用户去外部工具里改。Chat vs Workbench 五个层面差异:布局(单栏 vs 三栏);输入(textarea vs 多入口 @);输出(气泡 vs 可编辑资产);持久化(session vs 项目);校验(无 vs reviewer 卡三态);输入多入口 = chat + 拖入文件 + 数据源 @ 引用。
