ChatGPT · GPT-5.6（思考程度可调） OpenAI 2026.08.06
  • 用一个滑块把「思考多深」交还给用户（08.06）—— 官方 release notes 记录：Plus / Pro 用户的 GPT-5.6 Sol 新增一个滑块，让用户自己选「ChatGPT 为这次回答投入多少思考」；同时事实更可靠、答案更聚焦。把原本藏在模型内部的「推理预算」变成一个用户可感、可调的控件。
  • 难题给一个显式的 Think 入口（08.06）—— Free / Go 用户本周默认切到 GPT-5.6 Luna，下周起获得无限文本对话，以及一个专门面向难题的 Think 按钮（受滥用防护限制）;把「要不要更用力想」做成一次显式点击，而非让用户去猜模型状态。
  • 明确圈定影响面（08.06）—— release notes 特别注明：本次只影响 ChatGPT 的聊天体验，Work 与 Codex 不随此变化;分线更新讲清「谁变了、谁没变」，便于用户评估影响。
「思考程度滑块 + Think 按钮」这组更新，核心是把一个过去完全黑箱的变量——模型的推理投入——变成用户能看见、能拨动的控件，给做 AI 交互的团队三条可迁移原则:① 把「隐性权衡」显性化为一个可调控件，而不是替用户偷偷决定——回答的快与准、省与深本是一对权衡，与其由系统一刀切，不如给一个滑块让用户按场景自选;凡是「快 vs 好」「省 vs 全」这类权衡，都值得考虑交还给用户一个旋钮。② 高成本动作要有「显式入口」，让用户主动触发而非系统猜——Think 按钮把「更用力思考」做成一次点击，既省算力也让用户对「这次会更慢但更好」有预期;别让昂贵行为悄悄发生，给它一个看得见的开关。③ 分线更新讲清影响面——明说「只动 Chat、Work / Codex 不变」，让用户精确知道自己的工作流是否受影响。把「隐性权衡」显性化为可调控件（思考程度滑块），而非系统替用户偷偷决定;高成本动作给「显式入口」（Think 按钮），主动触发而非系统猜;控件让用户对「更慢但更好」形成预期，降低等待焦虑;分线更新讲清影响面（只动 Chat、Work / Codex 不变）;把模型内部变量（推理预算）翻译成用户可感语言;默认档位随套餐分层（Sol / Luna），但把选择权尽量留给人。

ChatGPT · Voice 支持文件与 Projects OpenAI 2026.08.07
  • 语音对话里也能「带资料进来」（08.07）—— 官方 release notes 记录：GPT-Live 语音现支持上传文件，可在通话中分析文件内容或就其提问;语音从「凭空口头问答」升级为「可以指着一份资料说话」。
  • 语音接入 Projects 的既有上下文（08.07）—— 语音可在 Projects 中使用，引用最近的项目对话、来源与项目指令;把文字端已经沉淀的项目上下文，平移进语音这条通道。
  • 后台语音有「还在吗」的安全兜底（08.07，移动端）—— 同批更新里，移动端能识别后台语音对话是否已不活跃、确认用户是否还在，无响应则结束会话;可在设置随时关闭 Background conversations。
语音这条线过去最大的短板是「只能凭空聊、带不进资料、也接不上你已有的工作」，这次更新正好补上，给做多模态 / 语音交互的团队三条启示:① 让每一种输入通道都能「带上下文」，而不是各自为政——文字端能引用文件和项目，语音端就也该能;当一个新通道（语音）无法复用用户已沉淀的上下文（文件 / 项目），它就只是个玩具而非工作入口。通道可以不同，上下文应当共享。② 把成熟通道的能力「平移」到新通道，而非让新通道从零长起——直接把 Projects 的对话 / 来源 / 指令接进语音，是承认「用户的工作已经在那儿了」，让语音站在既有资产上。③ 无界面通道更要有「安全兜底」——后台语音「确认你还在、否则挂断」，是在一个看不见界面的场景里替用户守住隐私与资源;越是无屏 / 自动的交互，越需要显式的可关闭开关与主动的退出机制。让每种输入通道都能「带上下文」（语音也能上传文件 / 引用 Projects），通道不同但上下文共享;把成熟通道能力「平移」到新通道，让新通道站在既有资产上而非从零长起;无界面通道要有「安全兜底」（后台语音确认在场否则挂断）;自动 / 无屏交互配显式可关闭开关（Settings → Voice）;语音从「口头问答」升级为「带资料的工作入口」;隐私与资源在无人值守场景由产品主动守护。

ChatGPT · 对话内查订餐厅 OpenAI（OpenTable / Resy / Yelp） 2026.08.10
  • 把「查—比—订」压进一段对话（08.10）—— 官方 release notes 记录：在聊天里说清地点、时间、人数与偏好，可直接在回答中看到可预订时段，追问即可收窄选项或核对某家店，选中一个合适的时间点即完成预订。
  • 结果就地可操作，不跳出去（08.10）—— 可预订时段直接展示在回答里、选中即订，把原本「切到订餐 App / 网站」的跳转折叠进对话流;让「决定」和「执行」发生在同一处。
  • 覆盖范围与边界说清楚（08.10）—— 全端（移动 / 网页 / 桌面）铺开;OpenTable 全球、Resy 限美国、Yelp 限美加;ChatGPT Work 不含餐厅预订搜索。明确圈定「哪些区域 / 哪些套餐能用」。
餐厅预订这类「查信息 → 比选项 → 下单」的经典多步任务被压进一段对话，给做任务型 / Agent 类产品三条启示:① 把「决定」与「执行」收进同一处，消灭跳转断点——过去查到餐厅还要切到订餐 App 再操作一遍，这里可预订时段直接在回答里、选中即订;凡是「查到了还得去别处操作」的地方，都是一个可被就地执行替代的断点。② 用追问收窄，替代一次性填满长表单——不逼用户先填齐所有条件，而是先给结果、再靠追问逐步收窄（换菜系 / 改时段 / 核对某家）;对话式收窄比长表单更贴合真实决策是「边看边改」的过程。③ 能力边界前置说清——明确哪些区域 / 哪些渠道 / 哪些套餐可用（Work 不含），避免用户在不可用场景里空试;清楚的边界本身就是体验的一部分。把「决定」与「执行」收进同一处，消灭「查到再去别处操作」的跳转断点;用对话式追问逐步收窄，替代一次性长表单，贴合「边看边改」的真实决策;可预订时段就地展示、选中即订，动作不离开对话流;能力边界前置说清（区域 / 渠道 / 套餐差异，Work 不含）;第三方能力（OpenTable / Resy / Yelp）作为工具被编排进对话;多步任务收敛为一段自然语言交互，降低跨应用成本。

Gemini Notebooks · Workspace Studio 自动补源 Google Workspace 2026.08.07
  • 把「手动逐条加来源」变成一个可编排的步骤（08.07）—— 官方 Workspace Updates 记录：过去保持 Gemini Notebook 更新要一条条手动加来源，现在新增「Add a source to Gemini Notebook」步骤，可纳入 Workspace Studio 的定时 / 循环工作流。
  • 来源类型覆盖文本 / Drive / 网页（08.07）—— 该步骤支持把纯文本、Drive 文件链接、通用 YouTube 或网页 URL 作为来源自动加入笔记本，确保笔记本始终跟上最新内容。
  • 默认可用、按已有权限治理（08.07）—— 管理员若已允许 Gemini for Workspace 步骤则此步骤默认可用;Rapid / Scheduled Release 域自 08.06 起分阶段推送。
这条更新看似只是「Notebook 多了一个自动化步骤」，实则把知识库维护从「一次性手动搬运」升级为「持续自动同步」，给做知识 / 内容型产品三条启示:① 把「重复维护」自动化成一个可编排步骤，而不是让用户永远手动搬运——知识库最大的隐性成本是「让它保持最新」，逐条加源是典型的重复劳动;把它做成一个可放进定时工作流的步骤，等于承认「维护」本身值得被自动化。凡是需要用户周期性手动更新的地方，都值得问一句「能不能编排」。② 让「新鲜度」成为系统职责，而非用户纪律——依赖用户记得手动更新，笔记本迟早过期;把补源接进循环工作流，是把「保持最新」从人的纪律变成系统的默认行为。③ 自动化沿用既有权限边界，不另开口子——按管理员对 Gemini 步骤的既有授权来治理，让自动化落在已有的治理框架内而非绕过它;能力自动化的同时，权限模型要保持一致。把「重复维护」自动化成可编排步骤（Add a source 步骤进定时工作流），而非永远手动搬运;让「新鲜度 / 保持最新」成为系统职责，而非依赖用户纪律;来源类型统一抽象（文本 / Drive / YouTube / 网页 URL），降低接入心智;自动化沿用既有权限边界（按 Gemini 步骤授权治理），不另开口子;知识库从「一次性搬运」升级为「持续同步」;把周期性人工动作识别为可自动化的候选。

Google Workspace · 协作反馈更「有上下文」 Google Workspace（Weekly Recap） 2026.08.07
  • Meet 纪要自动嵌入「所讲内容的截图」（08.07）—— 官方 Workspace Updates 周报记录：「Take notes for me」升级为可自动捕获并把演示内容的截图直接放进会议纪要文档;让 AI 纪要不只有文字，还带上「当时屏幕上是什么」。
  • Drive 视频支持「时间戳评论」（08.07）—— 网页端 Drive 视频现可把评论锚定到具体时间点，让视频协作更直接、精确、有上下文;评论不再泛指「这个视频」，而是「第几分几秒这里」。
  • 均为窗口内一手公告（08.07）—— 两条均出自 08.07 的 Workspace Updates Weekly Recap，指向同一主题：给协作反馈补上「它到底指哪儿」的上下文。
Meet 纪要嵌截图、Drive 视频加时间戳评论，看似两件小事，底层是同一条 UX 主张——反馈与记录要「锚定到具体对象」，而不是悬空，给做协作 / 文档 / 评审类产品两条启示:① 让每一条反馈都「有坐标」，消灭「你说的是哪个」的来回——时间戳评论把「视频里第几秒」变成可点击的锚点，纪要截图把「当时讲的是哪一页」固定下来;凡是反馈容易脱离对象、需要额外解释「指的是哪儿」的场景，都该给它一个精确锚点。② AI 生成的记录要保留「原始现场」，而不只是文字转述——纯文字纪要会丢失「屏幕上到底展示了什么」，自动嵌截图是把视觉现场一起留档;AI 摘要越是概括，越要给用户一条回到原始上下文的路径。这两条对我们的设计评审、录屏反馈、会议纪要类场景都直接可用。让每条反馈都「有坐标 / 锚点」（视频时间戳评论），消灭「你说的是哪个」的来回;AI 生成记录保留「原始现场」（纪要自动嵌截图），而非只留文字转述;把「指哪儿」的上下文固化进产物，降低协作解释成本;评论 / 批注锚定到具体对象（时间点 / 页面），而非悬空指向整体;AI 摘要越概括，越要留一条回到原始上下文的路径;协作反馈的精确性来自「可定位」而非「说得更多」。

Google Sheets · Connected Sheets — 从「懂数据库的人」到「看得懂的人」的可读性重构

Connected Sheets · 列表参数与列别名 Google Workspace 2026.08.11
  • 列表参数：让非技术协作者也能自助筛选（08.11）—— 官方 Workspace Updates 记录：查询里可用「列表参数」引用一段网格区域的多值（每个单元格即一个值），数据管理员可配置输入表，让协作者 / 终端用户通过下拉或单元格选项做高级筛选，无需改动底层查询;更多人可独立自助获取洞察。
  • 列别名：给晦涩字段名换上可读标签（08.11）—— 可直接在 Connected Sheet 里为 BigQuery 列名起别名，用「面向展示」的标签替换难懂的数据库字段名，且不改动底层数据库引用;公式与输入里新旧名皆可引用。
  • 无需管理员或用户额外设置（08.11）—— 两项均无管理员 / 用户开关，面向全体 Workspace 客户与个人账号，预计 08.15 前完成推送。
列表参数与列别名这两个「可用性小改」，共同解决一个老问题：数据库的能力被「懂 SQL / 懂字段名的人」垄断，普通协作者用不上，给做数据 / B 端工具三条启示:① 把「改查询」降级为「选选项」，让非技术用户也能自助——列表参数让筛选变成在单元格里选值、而非改底层 SQL，等于把一个需要技术背景的动作降维成人人会做的操作;凡是「只有懂技术的人才能调」的地方，都值得想办法做一层「选项化」的外壳。② 用「展示层别名」隔离「底层真名」，可读不牺牲一致——列别名让界面显示可读标签、底层仍指向真实字段，是典型的「表现与实现分离」;既照顾了广泛受众的可读性，又不破坏数据引用的稳定。③ 好的可用性改进往往「零配置」——无管理员 / 用户开关、默认对所有人生效;降低门槛的功能，本身也该是零门槛可用的。把「改查询」降级为「选选项」（列表参数），让非技术用户自助筛选;用「展示层别名」隔离「底层真名」（列别名），可读不牺牲引用一致;表现与实现分离，界面可读、底层稳定;好可用性改进往往「零配置」默认生效，降低门槛的功能也该零门槛;让数据能力从「懂技术的人」扩散到「看得懂的人」;把需要专业背景的动作，包一层人人可用的外壳。

Google Sheets · Excel 导入保留表与联动透视表 Google Workspace 2026.08.11
  • Excel 表格无缝导入为 Sheets 表格（08.11）—— 官方 Workspace Updates 记录：以往从 Excel 转换时，Excel 表格不会导入成 Sheets 表格，用户因此丢失表格的结构与格式收益;现在可无缝导入。
  • 基于表格区域的透视表也能完整导入（08.11）—— 以往联动到表格的透视表会被替换为静态网格，现在 Sheets 完整支持导入基于表格区域的 Excel 透视表，联动关系得以保留。
  • 导入即用，无需手动重建（08.11）—— 更新确保数据结构在导入后保持完整且格式美观，「拿来即用、无需手动重构」;面向全体 Workspace 客户与个人账号。
「导入 Excel 时保住表格与联动透视表」这件事，表面是兼容性、实则是一条关键的迁移体验原则:① 迁移 / 导入要「保住结构」，而不只是搬运数据——把带表格、带联动透视表的文件转过来却退化成静态网格，等于让用户在新工具里从头重建一遍;真正无摩擦的导入，应连同「数据之间的关系与结构」一起迁移，而非只搬内容。② 「拿来即用」是迁移体验的验收标准——官方把目标定为「导入后立即可用、无需手动重构」，正说明迁移的成败不在「能不能打开」，而在「打开后要不要返工」;凡是导入后还得让用户手动修一遍格式 / 重建关系的，都是没做完的迁移。③ 降低迁移成本，就是降低用户「换过来」的决策阻力——迁移越无损，用户从竞品切换的心理门槛越低;对任何想承接存量用户的产品，导入保真度都是一条隐形的增长杠杆。迁移 / 导入要「保住结构与关系」（表格 + 联动透视表），而非只搬数据;「拿来即用、无需手动重构」作为迁移体验的验收标准;导入后需返工 = 没做完的迁移;降低迁移成本即降低用户「换过来」的决策阻力;结构化对象（表 / 透视表）跨工具保真是隐形增长杠杆;兼容性问题本质是「换工具后要不要重来一遍」的体验问题。

对我们的启示

从 08.06 ~ 08.12 这一周产品动态中提炼的 4 条具体、可执行的设计建议

Insight · 01
↗ GPT-5.6 思考滑块 · 把隐性权衡交还用户
把「隐性权衡」显性化为一个可调控件
GPT-5.6 用一个滑块把「模型为这次回答投入多少思考」交还给用户，Think 按钮把「更用力想」做成一次显式点击:① 凡是「快 vs 好」「省 vs 全」这类权衡，都值得考虑交还用户一个旋钮——回答的深浅本是一对权衡，与其由系统一刀切，不如让用户按场景自选，把藏在内部的推理预算变成可感、可调的控件。② 高成本动作要有「显式入口」，让用户主动触发而非系统猜——Think 按钮既省算力，也让用户对「这次会更慢但更好」有预期;别让昂贵行为悄悄发生。③ 分线更新讲清影响面——明说「只动 Chat、Work / Codex 不变」，让用户精确评估自己的工作流是否受影响。把「隐性权衡」显性化为可调控件（思考程度滑块），而非系统偷偷决定;高成本动作给「显式入口」（Think 按钮），主动触发而非系统猜;控件让用户对「更慢但更好」形成预期，降低等待焦虑;把模型内部变量翻译成用户可感语言;默认档位可分层，但把选择权尽量留给人;分线更新讲清影响面，便于评估。
Insight · 02
↗ ChatGPT Voice / 餐厅预订 · 通道共享上下文、就地执行
让每种通道都能带上下文，把执行收回原地
ChatGPT Voice 支持文件与 Projects、餐厅预订把「查—比—订」压进一段对话，指向同一主张——通道可以不同，上下文与执行应当收敛:① 让每种输入通道都能「带上下文」，而不是各自为政——文字端能引用文件 / 项目，语音端也该能;当新通道无法复用用户已沉淀的上下文，它就只是玩具而非工作入口。② 把「决定」与「执行」收进同一处，消灭跳转断点——可预订时段直接在回答里、选中即订，凡是「查到了还得去别处操作」的地方，都是可被就地执行替代的断点。③ 用追问收窄替代长表单——先给结果再逐步收窄，比一次性填满所有条件更贴合「边看边改」的真实决策。让每种通道都能「带上下文」（语音也能上传文件 / 引用 Projects），通道不同但上下文共享;把「决定」与「执行」收进同一处，消灭「查到再去别处操作」的跳转断点;用对话式追问逐步收窄，替代一次性长表单;成熟通道能力「平移」到新通道，让其站在既有资产上;无界面 / 自动交互配显式可关闭开关与安全兜底;第三方能力被编排进对话，多步任务收敛为一次交互。
Insight · 03
↗ Gemini Notebooks 自动补源 · 维护自动化
把「重复维护」自动化，让新鲜度成为系统职责
Gemini Notebooks 把「逐条手动加来源」做成一个可放进定时工作流的步骤，让笔记本自动跟上最新内容:① 把「重复维护」自动化成一个可编排步骤，而不是让用户永远手动搬运——知识库最大的隐性成本是「让它保持最新」;凡是需要用户周期性手动更新的地方，都值得问一句「能不能编排」。② 让「新鲜度」成为系统职责，而非用户纪律——依赖用户记得更新，内容迟早过期;把补源接进循环工作流，是把「保持最新」从人的纪律变成系统的默认行为。③ 自动化沿用既有权限边界——按管理员对 Gemini 步骤的既有授权治理，让自动化落在已有治理框架内而非绕过它。把「重复维护」自动化成可编排步骤，而非永远手动搬运;让「新鲜度 / 保持最新」成为系统职责，而非依赖用户纪律;来源类型统一抽象（文本 / Drive / YouTube / 网页），降低接入心智;自动化沿用既有权限边界，不另开口子;知识库从「一次性搬运」升级为「持续同步」;把周期性人工动作识别为可自动化的候选。
Insight · 04
