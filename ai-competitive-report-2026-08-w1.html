ChatGPT · GPT-5.6（思考程度可调） OpenAI 2026.08.06
  • 用一个滑块把「思考多深」交还给用户（08.06）—— 官方 release notes 记录：Plus / Pro 用户的 GPT-5.6 Sol 新增一个滑块，让用户自己选「ChatGPT 为这次回答投入多少思考」；同时事实更可靠、答案更聚焦。把原本藏在模型内部的「推理预算」变成一个用户可感、可调的控件。
  • 难题给一个显式的 Think 入口（08.06）—— Free / Go 用户本周默认切到 GPT-5.6 Luna，下周起获得无限文本对话，以及一个专门面向难题的 Think 按钮（受滥用防护限制）;把「要不要更用力想」做成一次显式点击，而非让用户去猜模型状态。
  • 明确圈定影响面（08.06）—— release notes 特别注明：本次只影响 ChatGPT 的聊天体验，Work 与 Codex 不随此变化;分线更新讲清「谁变了、谁没变」，便于用户评估影响。
「思考程度滑块 + Think 按钮」这组更新，核心是把一个过去完全黑箱的变量——模型的推理投入——变成用户能看见、能拨动的控件，给做 AI 交互的团队三条可迁移原则:① 把「隐性权衡」显性化为一个可调控件，而不是替用户偷偷决定——回答的快与准、省与深本是一对权衡，与其由系统一刀切，不如给一个滑块让用户按场景自选;凡是「快 vs 好」「省 vs 全」这类权衡，都值得考虑交还给用户一个旋钮。② 高成本动作要有「显式入口」，让用户主动触发而非系统猜——Think 按钮把「更用力思考」做成一次点击，既省算力也让用户对「这次会更慢但更好」有预期;别让昂贵行为悄悄发生，给它一个看得见的开关。③ 分线更新讲清影响面——明说「只动 Chat、Work / Codex 不变」，让用户精确知道自己的工作流是否受影响。把「隐性权衡」显性化为可调控件（思考程度滑块），而非系统替用户偷偷决定;高成本动作给「显式入口」（Think 按钮），主动触发而非系统猜;控件让用户对「更慢但更好」形成预期，降低等待焦虑;分线更新讲清影响面（只动 Chat、Work / Codex 不变）;把模型内部变量（推理预算）翻译成用户可感语言;默认档位随套餐分层（Sol / Luna），但把选择权尽量留给人。

ChatGPT · for Teens（13–17 岁专版） OpenAI 2026.08.18
  • 为未成年人做一个「默认更安全」的版本，而非加一堆开关（08.18）—— OpenAI 官方博客记录：估计或声明年龄在 13–17 的用户会自动进入 ChatGPT for Teens，内建年龄适配的模型护栏，减少接触有害 / 不适龄内容，并在自残、暴力、饮食失调等高风险领域加做产品干预。
  • 把「学习」而非「代写」设为默认姿态（08.18）—— 内建学习模式（引导式提问、分步支持），当青少年想「抄近路」完成作业时会被引导回协作解题；辅以测验、可视化、可设的「学习时段」，把工具定位成学伴而非答案机。
  • 健康使用 + 家长共管（08.18）—— 休息提醒、持续的「你在和 AI 对话」提示、敏感图片上传提醒；家长关联账号后可设「安静时段」、管理部分设置，并在有限高风险情形（含饮食失调）收到侧重「线下求助」的通知。
ChatGPT for Teens 不是「给现有产品套个青少年皮肤」，而是把安全与学习姿态做进默认，给做面向脆弱 / 特殊人群产品的团队三条启示:① 对高风险人群，用「默认更安全的独立体验」而非「让用户自己去调开关」—— 按年龄自动进入专版、护栏内建，承认「靠用户主动配置安全」在未成年人身上不成立;越是保护性场景，越该把安全做成默认路径而非可选项。② 用「产品姿态」引导正确使用，而非只做功能—— 把「学习模式 / 作业不走捷径」设为默认，是用交互姿态表达价值主张:工具想让你学会，而不是替你交差;好的引导藏在默认行为里。③ 持续的「AI 身份提示 + 情感边界」是信任底线—— 反复提示「你在和 AI 对话」、不使用浪漫语气、不鼓励情感依赖，是在关系层面替青少年设界;当产品可能被当作「人」，主动澄清边界本身就是一种保护。对高风险人群用「默认更安全的独立体验」，而非让用户自调开关;用「产品姿态」（学习模式 / 作业不走捷径）引导正确使用，价值主张写进默认行为;持续「AI 身份提示 + 情感边界」（不用浪漫语气 / 不鼓励依赖）作为信任底线;家长共管用「安静时段 + 高风险通知」把控制权分层交付;敏感能力侧重「线下求助」而非产品内闭环;安全干预聚焦高风险领域（自残 / 暴力 / 饮食失调）。

ChatGPT · 对话内查订餐厅 OpenAI（OpenTable / Resy / Yelp） 2026.08.10
  • 把「查—比—订」压进一段对话（08.10）—— The Verge 报道：在聊天里说清地点、时间、人数与偏好，可直接在回答中看到可预订时段，追问即可收窄选项或核对某家店，选中一个合适的时间点即完成预订。
  • 结果就地可操作，不跳出去（08.10）—— 回答里直接展示带图片 / 评论要点的可预订时段、选中即订，把原本「切到订餐 App / 网站」的跳转折叠进对话流;让「决定」和「执行」发生在同一处。
  • 接入三家、授权后成交（08.10）—— 与 OpenTable / Resy / Yelp 协作:Yelp 提供照片 / 菜单 / 评论，OpenTable / Resy 提供实时可订台位;仅在确认下单时按需授权分享姓名 / 邮箱 / 电话，保护聊天记录不外泄。
餐厅预订这类「查信息 → 比选项 → 下单」的经典多步任务被压进一段对话，给做任务型 / Agent 类产品三条启示:① 把「决定」与「执行」收进同一处，消灭跳转断点——过去查到餐厅还要切到订餐 App 再操作一遍，这里可预订时段直接在回答里、选中即订;凡是「查到了还得去别处操作」的地方，都是一个可被就地执行替代的断点。② 用追问收窄，替代一次性填满长表单——不逼用户先填齐所有条件，而是先给结果、再靠追问逐步收窄（换菜系 / 改时段 / 核对某家）;对话式收窄比长表单更贴合真实决策是「边看边改」的过程。③ 敏感信息「按需授权、临成交才给」——只在确认预订时才把姓名 / 邮箱 / 电话交给对应平台，聊天记录不外泄;把「什么时候、给谁、给什么」讲清，本身就是体验与信任的一部分。把「决定」与「执行」收进同一处，消灭「查到再去别处操作」的跳转断点;用对话式追问逐步收窄，替代一次性长表单，贴合「边看边改」的真实决策;可预订时段就地展示、选中即订，动作不离开对话流;敏感信息按需授权、临成交才给，保护聊天记录;第三方能力（OpenTable / Resy / Yelp）作为工具被编排进对话;多步任务收敛为一段自然语言交互，降低跨应用成本。

ChatGPT · Computer History（macOS） OpenAI 2026.08.14
  • 让助手「记得你刚做了什么」，省去反复解释（08.14）—— The Verge 报道：macOS 应用新增可选的 Computer History，经辅助功能把点击 / 键入 / 应用切换等交互事件汇成可搜索的时间线，让 ChatGPT 与 Codex 参考你的活动、帮你继续工作，还能就重复流程提议做成技能 / 自动化。
  • 只记「交互事件」，不截屏、不录音（08.14）—— 明确记录的是交互事件，而非截图 / 录屏 / 麦克风输入 / 系统音频;无痕浏览不纳入。它取代了此前靠截屏的 Chronicle 预览，把「记什么、不记什么」的边界一次讲清。
  • 默认关闭、用户可控、管理员前置授权（08.14）—— 默认 off，面向 Pro / Business / Enterprise;企业须管理员先授权成员才能开启;用户可从菜单栏暂停、自选纳入的应用与网站、分段删除时间线（近 10 分钟到全部）。当前 EEA / 英国 / 瑞士不可用。
Computer History 是一个「高价值但高敏感」的能力——让 AI 有记忆地帮你接着干，代价是它要看你的活动，给做记忆 / 上下文类功能三条启示:① 越是采集用户行为的能力，越要用「负面清单」讲清边界—— 官方主动声明「只记交互事件，不截屏 / 不录音 / 不含无痕」，用明确的「不做什么」建立信任;敏感能力的说明，重点不在「能干嘛」而在「不碰什么」。② 默认关闭 + 细粒度可控，是敏感能力的基本礼貌—— 默认 off、可暂停、可选纳入范围、可查看可删除，把控制权完整交到用户手里;不默认开启、不一刀切全采集。③ 企业场景「管理员前置授权」优先于个人自助—— 成员开启前须管理员放行，让治理走在能力之前;涉及组织数据的记忆能力，权限模型要先于功能落地。采集类能力用「负面清单」讲清边界（只记交互事件，不截屏 / 不录音 / 不含无痕）;默认关闭 + 细粒度可控（暂停 / 选范围 / 查看 / 删除），把控制权交给用户;企业场景「管理员前置授权」优先于个人自助;合规地域差异前置说清（EEA / 英国 / 瑞士暂不可用）;敏感能力的信任来自「不碰什么」而非「能干什么」;记忆让助手「接着干」，减少重复交代上下文的成本。

Claude · Cowork 扩展 + Gmail / Drive Anthropic 2026.08.19
  • 把浏览器插件升级为「跨端接续」的 Cowork（08.19）—— The Verge 报道：原 Chrome 扩展更名为 Claude Cowork，会把对话存进历史，让你在桌面、网页与移动 App 之间接着聊同一段工作，而非各端各聊各的。
  • Claude 在 Gmail / Google Drive 上能做更多（08.19）—— 报道称 Claude 与 Gmail、Google Drive 的打通进一步加深，把助手接进用户日常已在用的邮件与网盘资产。
  • 分层放量（08.19）—— Claude Cowork 今日面向 Max 与 Team 用户开放，未来数周覆盖 Pro 用户;按套餐分批铺开。
Cowork 把「一个浏览器插件」升级成「跨端连续的工作伙伴」，给做助手 / 效率类产品三条启示:① 让上下文「跟人走」，而非「跟设备走」—— 把对话存进历史、在桌面 / 网页 / 移动间接续，等于承认工作是跨设备发生的;当同一段任务在不同端断成几截，助手就退回成工具。② 接进用户「本就在用的资产」，而非另起炉灶—— 直接在 Gmail / Drive 上做事，是去用户资料所在处工作，而非逼用户把内容搬进来。③ 分层放量是控风险的常规动作—— 先 Max / Team、再 Pro，让高价值 / 高信任人群先用、逐步扩面;能力越贴近用户数据，越值得分批验证。让上下文「跟人走」而非「跟设备走」（对话存历史、跨端接续）;接进用户「本就在用的资产」（Gmail / Drive），去资料所在处工作而非搬运;分层放量（Max / Team → Pro）控风险，高信任人群先用;浏览器插件升级为跨端连续的工作伙伴;把断裂的多端任务重新连成一段;能力贴近用户数据时，权限与放量都需谨慎。

「导入 Excel 时保住表格与联动透视表」这件事，表面是兼容性、实则是一条关键的迁移体验原则:① 迁移 / 导入要「保住结构」，而不只是搬运数据——把带表格、带联动透视表的文件转过来却退化成静态网格，等于让用户在新工具里从头重建一遍;真正无摩擦的导入，应连同「数据之间的关系与结构」一起迁移，而非只搬内容。② 「拿来即用」是迁移体验的验收标准——官方把目标定为「导入后立即可用、无需手动重构」，正说明迁移的成败不在「能不能打开」，而在「打开后要不要返工」;凡是导入后还得让用户手动修一遍格式 / 重建关系的，都是没做完的迁移。③ 降低迁移成本，就是降低用户「换过来」的决策阻力——迁移越无损，用户从竞品切换的心理门槛越低;对任何想承接存量用户的产品，导入保真度都是一条隐形的增长杠杆。迁移 / 导入要「保住结构与关系」（表格 + 联动透视表），而非只搬数据;「拿来即用、无需手动重构」作为迁移体验的验收标准;导入后需返工 = 没做完的迁移;降低迁移成本即降低用户「换过来」的决策阻力;结构化对象（表 / 透视表）跨工具保真是隐形增长杠杆;兼容性问题本质是「换工具后要不要重来一遍」的体验问题。

对我们的启示

从 08.06 ~ 08.19 这两周产品动态中提炼的 4 条具体、可执行的设计建议

Insight · 01
↗ GPT-5.6 思考滑块 · 把隐性权衡交还用户
把「隐性权衡」显性化为一个可调控件
GPT-5.6 用一个滑块把「模型为这次回答投入多少思考」交还给用户，Think 按钮把「更用力想」做成一次显式点击:① 凡是「快 vs 好」「省 vs 全」这类权衡，都值得考虑交还用户一个旋钮——回答的深浅本是一对权衡，与其由系统一刀切，不如让用户按场景自选，把藏在内部的推理预算变成可感、可调的控件。② 高成本动作要有「显式入口」，让用户主动触发而非系统猜——Think 按钮既省算力，也让用户对「这次会更慢但更好」有预期;别让昂贵行为悄悄发生。③ 分线更新讲清影响面——明说「只动 Chat、Work / Codex 不变」，让用户精确评估自己的工作流是否受影响。把「隐性权衡」显性化为可调控件（思考程度滑块），而非系统偷偷决定;高成本动作给「显式入口」（Think 按钮），主动触发而非系统猜;控件让用户对「更慢但更好」形成预期，降低等待焦虑;把模型内部变量翻译成用户可感语言;默认档位可分层，但把选择权尽量留给人;分线更新讲清影响面，便于评估。
Insight · 02
↗ 餐厅预订 / Google Drive 并排 / Ask Gemini · 入口与执行收敛
让每种通道都带上下文，把执行收回原地
这两周里 ChatGPT 餐厅预订把「查—比—订」压进对话、Google Drive 文件并排开在对话旁并连回源、Ask Gemini in Chat 做「面向全部工作的统一命令行」，共同指向一件事——入口与执行应当收敛:① 让每种通道都能「带上下文」，而不是各自为政——文字端能引用文件 / 项目，语音端、协作端也该能;当新通道无法复用用户已沉淀的上下文，它就只是玩具而非工作入口。② 把「决定」与「执行」收进同一处，消灭跳转断点——可预订时段直接在回答里选中即订、Drive 文件就地可读可改，凡是「查到了还得去别处操作」的地方，都是可被就地执行替代的断点。③ 「统一入口」的价值在于「不必离开」——把生成文档、排会、跨三方检索都收进一条对话，入口的统一不是堆功能，而是让任务在原地闭环。让每种通道都能「带上下文」，通道不同但上下文共享;把「决定」与「执行」收进同一处，消灭「查到再去别处操作」的跳转断点;「统一入口」价值在「不必离开」（Chat 内闭环文档 / 排会 / 检索）;外部资料「并排 + 连回源」优于「贴进输入框」;从「一问一答」升级到「说清目的 → 交回成品」;用对话式追问逐步收窄，替代一次性长表单。
Insight · 03
↗ Figma 社区技能 / 推荐资源 · 工作流即资产
把可复用工作流沉淀成技能，用轻信号收窄选择
Figma 这一双周把「AI 技能」当成一等资产运营——agent 可基于文件上下文造技能、发布到社区供 remix，管理员还能「推荐资源」，给设计工具 / 平台三条直接可用的启示:① 把「可复用的工作流」沉淀成技能，而非让每个人重复摸索——团队里那些反复出现的套路（研究 / 设计系统 / 交付），都值得被打包成一个能用 / 一键唤起的技能。② 「推荐资源」用轻量信号解决「该用哪个」的选择过载——对勾 + Tooltip 标注管理员推荐，比一份规范文档更能在用的当下给出指引;当可选项爆炸时，产品该主动收窄而非让用户自己筛。③ 把好设计设为默认——文本换行的 Balance / Pretty 把「修孤词、齐行」这类手动活做成默认可得的开关，是把专业判断内建进工具。把「可复用工作流」沉淀成技能（agent 造技能 / 社区分享），而非重复摸索;「推荐资源」用对勾 + Tooltip 轻信号解决「该用哪个」的选择过载;把好设计设为默认（Balance / Pretty 内建专业判断）;技能作为一等资产可发现 / 可创建 / 可治理;组织级推荐让规范落到「用的当下」而非文档里;用 / 唤起技能，降低复杂工作流的调用成本。
Insight · 04
↗ Computer History / 项目记忆可切换 · 敏感能力的信任设计
采集类能力用「负面清单 + 默认关闭 + 可控」建立信任
ChatGPT 的 Computer History 让 AI 有记忆地帮你接着干、项目记忆设置可事后在「默认 / 仅项目」间切换，两者都在回答同一个问题——当能力越贴近用户数据，信任该如何设计:① 越是采集用户行为的能力，越要用「负面清单」讲清边界——官方主动声明「只记交互事件，不截屏 / 不录音 / 不含无痕」，用明确的「不做什么」建立信任;敏感能力的说明，重点不在「能干嘛」而在「不碰什么」。② 默认关闭 + 细粒度可控，是敏感能力的基本礼貌——默认 off、可暂停、可选范围、可查看可删除，把控制权完整交到用户手里;记忆边界还应可事后调整，而非开局定死。③ 企业场景「管理员前置授权」优先于个人自助——涉及组织数据的记忆能力，权限模型要先于功能落地。采集类能力用「负面清单」讲清边界（只记交互事件，不截屏 / 不录音 / 不含无痕）;默认关闭 + 细粒度可控（暂停 / 选范围 / 查看 / 删除），把控制权交给用户;「记忆边界」做成可事后切换的开关（默认 / 仅项目），而非开局定死;企业场景「管理员前置授权」优先于个人自助;合规地域差异前置说清（EEA / 英国 / 瑞士暂不可用）;敏感能力的信任来自「不碰什么」而非「能干什么」。
